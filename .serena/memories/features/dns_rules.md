# DNS routing, filters matcher, and configuration schema
- disabled groups are excluded from compilation, DomainNames/matcher/cache snapshots. Apply cancels DomainGeneration and old service queries.
- Empty model.DNS.Route = legacy direct upstream + system fallback; direct = explicit without system fallback; connection + Connection ID, Failure strict/direct. connection supports only DoH/DoT. Named upstreams in explicit modes require Bootstrap host→IP maps, preserving TLS hostname. strict forbids direct in chains; container/unknown raw outbound types are rejected for DNS to avoid hidden direct traffic. dnsDial uses sing-box outbound/selector and rejects selected direct: direct fallback is a separate dnsfront leg with audit/status events. REFUSED/SERVFAIL never silently switch provider.
- dnsfront transport.go uses separate HTTP2 pools for primary/direct-fallback; lifetime canceled on Close, normal TLS root verification. DoT cancellation captures immutable rawConn. Active RefreshDomains follows the same routing policy (formerly direct resolver).
- Optional DNS BlockEncrypted IPv4 port853 guard: separate KEENPROXY_DNS_GUARD INPUT/FORWARD chain; conntrack original port catches REDIRECT. Own OUTPUT remains allowed. FirefoxCanary NXDOMAIN. DoH443/IPv6 bypass prevention is not promised.
- internal/lists/suffix.go: compact sorted suffix matcher and Parse supporting plain/hosts/||domain^/@@||domain^ (8MiB/200k limits). Cosmetic rules are rejected, never converted to DNS blocks. No product feature uses it yet; presets, local presets, resource exchange, ad filter lists and the DNS check endpoint were removed.
- Config files are written with schema_version 2, strict KnownFields, exactly one document. A schema-1 file that still loads is used as is and copied byte for byte to config.v1.yaml (0600, never overwritten; timestamped name otherwise) before the first write; installer placeholders without connections/subscriptions are not backed up. A schema-1 or unreadable file that no longer loads is reset at startup: the original stays as config.v1.yaml, and api.listen, lan and the first valid subscription are carried into a fresh v2 file. A broken schema-2 file is an error. -dry-run reports a planned reset without writing. The installer restores its pre-update snapshot on failure. Only a target that cannot read schema 2 at all (its dry run rejects a file holding just schema_version: 2) gets the newest kept config.v1*.yaml, switched atomically (the newer file is kept as config.v2*.yaml); a target that reads schema 2 but rejects the file is refused. A fresh install has no v1 backup, so such a rollback is refused.
- YAML import/export/previous endpoints are removed; daemon.Apply still saves a .previous (0600) before new YAML. The API stays JSON.
