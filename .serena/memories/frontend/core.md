# API and UI
- The Vue panel, Vite demo and Go api.Demo are removed; a server-rendered UI is pending. Do not reintroduce a SPA build. Until it lands, every page path (outside /api) returns 503 "KeenProxy interface is being rebuilt" (api.rebuildingUI) to trusted loopback and to signed-in KeeneticOS accounts.
- Trusted loopback = loopback RemoteAddr AND Host 127.0.0.1, ::1 or localhost (any port). No other header counts; Authorization is ignored. A local forward or reverse proxy that relays to 127.0.0.1 with a loopback Host is trusted too (documented residual risk).
- /api is the loopback-only control API (memory gate, netns integration, local scripts; the installer does not call it). Non-loopback clients get 403 "local access only" there, with or without a KeeneticOS session (503 in the unavailable mode). Only GET /api/session and POST /api/logout (api.publicRoutes) answer browsers.
- One middleware (api.Server.authorize, policy in decide) authorizes every path. A cross-origin write (http.CrossOriginProtection: not GET/HEAD/OPTIONS, foreign Sec-Fetch-Site or Origin) is refused first, loopback included. Refusals are JSON under /api and short text on pages.
- KeeneticOS sign-in is on by default on Keenetic: origin from the first private IPv4 of lan.interface (the address -url prints), WebUI assumed on port 80. -keenetic-auth-origin or KEENPROXY_KEENETIC_AUTH_ORIGIN overrides it, "off" disables it; on Entware /opt/etc/keenproxy/keenproxy.env persists that. Other systems: off. An origin that cannot work means 503 for browsers while loopback keeps working.
- Roles (api.RoleFrom) come from KeeneticOS user tags: http+cli without readonly/manager manages; http with readonly or manager views (writes 403); anything else is denied. Roles apply to pages; secrets render only on an explicit reveal by a managing account.
- Removed: panel token, -key, trusted networks, POST /api/login, presets, resource exchange, ad filter lists and panel-only endpoints (GeoIP lookup, domain preview, YAML import/export/previous, DNS check, journal stream/export). api.token_file and api.no_token_from are accepted and ignored.
- Kept for loopback automation: GET/PUT /api/config, /api/status, /api/stats, /api/stats/hosts, GET /api/journal/{kind}, and the support ZIP. Unknown /api/ routes return 404 to loopback.
- The shared draft/Apply workflow stays the contract for the future UI: one complete config PUT, no separate writes.
