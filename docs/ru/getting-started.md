# Начало работы

Bootstrap устанавливает релиз KeenProxy для вашей архитектуры и сверяет загруженные файлы с контрольными суммами релиза. Для сборки ветки `master` используйте команды из README. [Релизы на GitHub](https://github.com/LokiVPN/keen-proxy/releases) · [Сборка из исходников](https://github.com/LokiVPN/keen-proxy#build-and-try-the-interface)

## Экспериментальная поддержка OpenWrt { #experimental-openwrt-support }

KeenProxy требует **не менее 256 МиБ общей оперативной памяти** на роутерах OpenWrt и Keenetic/Netcraze, а также достаточного места для бинарника и его данных. В релизах доступны обычные сборки и lite для Linux на x86-64 (`amd64`, базовый уровень v1), 32-битной x86 (`386`, требуется SSE2), ARM32 (ARMv5 и новее, soft float, суффикс `armv5`), ARM64 (`arm64`), MIPS little-endian (`mipsle`, soft float) и MIPS big-endian (`mipsbe`, soft float).

Нативная установка и обновление из панели на OpenWrt используют системную оболочку и procd без Entware. Нативный вариант и Entware поддерживают шесть перечисленных архитектур релиза. Для перехвата по-прежнему нужны совместимые `iptables`, `iptables-restore` и поддержка в ядре. Проверьте перехват на тестовом клиенте с вашей прошивкой, особенно если она использует firewall4. Нативный backend nftables не добавляется. [Документация OpenWrt по Netfilter](https://openwrt.org/docs/guide-user/firewall/netfilter_iptables/netfilter_management)

Необязательный хук netfilter для NDM относится к совместимым прошивкам Keenetic/Netcraze. На OpenWrt без NDM он выключен и не создаёт файлов хука или событий NDM; обычный сторож продолжает проверять правила каждые 30 секунд по умолчанию. Интеграция с hotplug или firewall4 OpenWrt не устанавливается. Подробнее о [восстановлении правил](network-flow.md#how-firewall-rules-recover-after-a-firmware-change).

### Нативная установка OpenWrt { #native-openwrt-installation }

Сохраните доступ для восстановления по SSH/LAN и резервную копию конфигурации. Остановите другие перехватчики DNS и трафика: как только политика сети или устройства включает устройства, KeenProxy перехватывает их DNS. На постоянном разделе overlay должно хватать места для бинарника, новой сборки и копии для отката; свободного места в `/tmp` недостаточно.

Установите `curl`, сертификаты CA и совместимые утилиты iptables через менеджер пакетов своей прошивки (`opkg` или `apk`). Названия пакетов зависят от выпуска; распространённые варианты — `curl`, `ca-bundle` и `iptables-nft`. Для REDIRECT нужна поддержка NAT, а для UDP TPROXY — соответствующие модули TPROXY/mangle. Установка пакета сама по себе не доказывает совместимость с прошивкой.

Перед установкой проверьте окружение:

```sh
uname -m
df -h /overlay /usr
free
test -x /sbin/procd && test -f /etc/openwrt_release
test -x /usr/sbin/iptables-restore
/usr/sbin/iptables -t nat -S
```

Затем выполните от имени root:

```sh
curl -fsSL https://raw.githubusercontent.com/LokiVPN/keen-proxy/master/tools/bootstrap.sh | KEENPROXY_PLATFORM=openwrt /bin/sh
```

Установщик размещает `/usr/bin/keenproxy`, включает автозапуск `/etc/init.d/keenproxy` через procd и запускает службу. Контрольные суммы и конфигурация проверяются до замены работающей версии. При ошибке запуска восстанавливаются предыдущие файлы и служба. В обе сборки, full и lite, встроен TrustTunnel; внешний клиент не нужен.

Начальная конфигурация — `/etc/keenproxy/config.yaml` с `lan.interface: br-lan`. Если в прошивке другое имя моста LAN, измените его. Существующая конфигурация сохраняется. CLI по умолчанию использует пути Entware, поэтому нативный конфиг нужно указать явно:

```sh
keenproxy --url -config /etc/keenproxy/config.yaml
/etc/init.d/keenproxy status
```

Для обновления повторите ту же команду. Чтобы выбрать релиз и вариант, добавьте к `/bin/sh` аргументы `-s -- --version vX.Y.Z --lite`; для удаления — `-s -- --uninstall`. Удаление останавливает службу, отключает автозапуск и удаляет бинарник и init-скрипт, сохраняя настройки. Обновление и расписание из панели работают по инструкции ниже.

На OpenWrt страницы управления доступны через [SSH-туннель](user-guide.md#ssh-tunnel). После подключения перейдите к [первой настройке](#first-configuration).

Для нативных транзакций нужен файл релиза `keenproxy.openwrt` с контрольной суммой. Более старые релизы без него не подходят для нативной установки и отката; отказ оставляет работающую версию без изменений. Запись о релизе и настройки обновления хранятся постоянно в `/usr/share/keenproxy/`. Правила, журналы и производные данные в `/var/lib/keenproxy/` на OpenWrt обычно не переживают перезагрузку.

Автоопределение сохраняет существующую установку под управлением Entware на OpenWrt, а не переносит её автоматически. `KEENPROXY_PLATFORM=openwrt` явно выбирает нативную установку. Не запускайте экземпляры Entware и OpenWrt одновременно. Дальнейшие инструкции по подготовке и команды оболочки Entware относятся только к варианту Entware.

## Подготовка роутера

### Железо и прошивка

- **Процессор.** Установщик поддерживает шесть перечисленных архитектур релиза. Нужен соответствующий Linux userspace; для 32-битной x86 требуется SSE2. Для MIPS проверьте порядок байтов по архитектуре пакетов или документации модели.
- **Прошивка.** Нужна модель Keenetic или Netcraze с компонентом поддержки открытых пакетов (OPKG), оболочкой Entware и совместимыми утилитами `iptables`. Для перехвата TCP используется REDIRECT. Для перехвата UDP в режиме `tproxy` дополнительно нужны поддержка TPROXY в ядре и маршрутизация по политикам.
- **Накопитель.** Используйте внешний USB-накопитель для Entware и KeenProxy. Сравните размер файла из релиза со свободным местом на `/opt` и оставьте запас для Entware, конфигурации, правил, списков фильтрации и копии для отката. Сборка lite занимает меньше места и поддерживает меньше протоколов.
- **Оперативная память.** Не менее **256 МиБ общей памяти роутера**, в том числе для lite. Это нижняя граница аппаратных требований, а не гарантия работы любой нагрузки. Проверьте доступную память при работающих штатных службах; оставьте запас для прошивки, движка, соединений и включённых списков. При первом тесте с вашей конфигурацией следите за расходом памяти. Рекомендация Go по памяти в 768 МиБ по умолчанию не является требованием к физической памяти или жёстким пределом RSS.

**Рекомендуемый компонент прошивки.** Включите **«Модули ядра для Netfilter»** вместе с OPKG, если компонент доступен для вашей модели. Он добавляет поддержку фильтрации пакетов в ядре для работы `iptables`. Утилиты Entware нужны отдельно. Сверьтесь со списком компонентов своей модели. [Описание компонентов KeeneticOS](https://support.keenetic.com/hopper/kn-3810/en/16327-os-component-description.html)

Если настройки не применяются при включённом перехвате UDP, см. [диагностику TPROXY на Keenetic](troubleshooting.md#keenetic-tproxy-apply).

Подготовьте раздел ext4 по инструкции ниже, включите компонент OPKG, положите архив установщика для своей модели в папку `install` на разделе и выберите этот раздел в менеджере OPKG. Если выбрали этот вариант, проверьте свободное место на `/opt` до установки KeenProxy. В инструкциях производителя описана установка через менеджер OPKG, командную строку и из архива. **Как подготовить флешку на самом роутере.** На поддерживаемых моделях с KeeneticOS или NetcrazeOS 5.1 и новее заранее установите компоненты поддержки файловой системы Ext и утилит для EXT4. Подключите флешку, откройте **Управление → Накопители и устройства**, выберите нужный раздел, нажмите **Форматировать** и укажите **EXT4**. Форматирование стирает данные на выбранном разделе, поэтому заранее сделайте резервную копию. Если на роутере нет этой функции, отформатируйте флешку в ext4 на компьютере. [Инструкция Netcraze по форматированию](https://support.netcraze.ru/titan-se/nc-4210/ru/100924-formatting-and-checking-a-file-system-on-a-usb-drive.html)

### Проверка перед установкой KeenProxy

После установки Entware подключитесь к его оболочке из локальной сети и смените начальный пароль. Сохраните резервную копию настроек роутера и локальный доступ для восстановления. Перед копированием KeenProxy выполните команды, которые только выводят информацию:

```sh
uname -m
opkg print-architecture
df -h /opt
free
command -v iptables
command -v iptables-restore
iptables -t nat -S
```

Проверьте архитектуру, свободное место, доступную память и наличие утилит для управления межсетевым экраном. Начните с примера конфигурации и замените параметры соединений своими в приватном окружении.

Последняя команда выводит правила IPv4 NAT без их изменения. Для режима `tproxy` проверьте также, что `iptables -t mangle -S` выполняется успешно. Доступ к таблицам — предварительная проверка. Работу REDIRECT или TPROXY проверьте на трафике тестового клиента.

## Установка и обновление с GitHub { #install-or-update-from-github }

Если `curl` и сертификаты ещё не установлены, добавьте их из оболочки Entware под `root`.

```sh
opkg update && opkg install curl ca-bundle ca-certificates
```

Перед установкой остановите другие службы, которые перехватывают трафик или DNS. KeenProxy перехватывает DNS только тех устройств, которые входят в политику сети или устройства; в начальной конфигурации таких нет, поэтому до их добавления ничего не перехватывается. Запустите скрипт после публикации релиза. [Релизы](https://github.com/LokiVPN/keen-proxy/releases)

```sh
curl -fsSL https://raw.githubusercontent.com/LokiVPN/keen-proxy/master/tools/bootstrap.sh | /opt/bin/sh
```

Установщик читает `BUILD_INFO.txt` последнего опубликованного релиза, определяет архитектуру и сверяет файлы релиза с `SHA256SUMS`. Он устанавливает недостающие утилиты `iptables` из Entware, создаёт начальную конфигурацию при её отсутствии и регистрирует и запускает `S99keenproxy` через механизм служб Entware. TrustTunnel работает внутри sing-box-lx, отдельный клиент не устанавливается. После установки и обновления из командной строки скрипт выводит URL панели, если установленная сборка может его определить. См. [доступ к панели](user-guide.md#access-the-panel).

При чистой установке bootstrap создаёт начальный файл `/opt/etc/keenproxy/config.yaml`. KeenProxy подставляет значения по умолчанию при чтении и записывает новые конфигурации с `schema_version: 2`. Чтобы войти и включить маршрутизацию, перейдите к [первой настройке](#first-configuration).

Для обновления повторите ту же команду. Конфигурацию, которую этот релиз не может прочитать, служба при запуске сбрасывает в памяти; сохранённая подписка затем направляет домашнюю сеть по правилам своего провайдера. Сам файл меняется только при первом сохранении, которое оставляет оригинал как `config.v1.yaml` (кроме файла со стартовыми настройками установщика), поэтому при откате обновления до этого момента старый релиз прочитает свой файл. См. [схема конфигурации 2 и откат](development.md#config-schema). Установщик этого релиза также делает снимок конфигурации перед установкой и восстанавливает его при неудачном обновлении. Установщик проверяет новую сборку до остановки службы. При ошибке запуска он пытается вернуть предыдущие файлы и запустить прежнюю службу. Экземпляр KeenProxy, запущенный вручную, нужно остановить перед переходом на установщик.

Чтобы выбрать версию, замените `vX.Y.Z` на опубликованный тег. Флаг `--lite` выбирает облегчённую сборку без QUIC/HTTP/3. `--without-trusttunnel` принимается для существующих обновляторов и скриптов, но больше не меняет состав установки: TrustTunnel встроен. `--trusttunnel-only` больше не принимается.

```sh
curl -fsSL https://raw.githubusercontent.com/LokiVPN/keen-proxy/master/tools/bootstrap.sh | /opt/bin/sh -s -- --version vX.Y.Z
```

Дождитесь появления файлов установщика и контрольных сумм в релизе. Если они ещё публикуются, повторите команду позже. Для управления службой используйте `/opt/etc/init.d/S99keenproxy` с командой `status`, `start`, `stop` или `restart`. Инструкции для ручной установки есть в корневом README. [Справка по установке](https://github.com/LokiVPN/keen-proxy#configuration-and-router-installation)

В Entware при запуске служба пытается поднять лимит открытых файлов процесса до 8192, не снижая более высокие лимиты. Если система не разрешает повышение, служба выдаёт предупреждение и всё равно запускается. Фактический лимит указан в строке `Max open files` файла `/proc/<PID>/limits` процесса KeenProxy.

## Обновление из панели { #update-from-the-panel }

В установке под управлением Entware или нативного OpenWrt раздел **Диагностика → Обновления** показывает текущую версию, доступный стабильный релиз и предыдущую установленную версию, если она записана. Если текущая сборка ещё не умеет обновляться из панели, один раз обновите её установщиком из командной строки. Чтобы иметь возможность откатиться к старому релизу, перед обновлением запустите новый установщик с точным тегом и вариантом уже установленной сборки. Для нативного OpenWrt в целевом релизе также должен быть файл службы procd.

Для установки, отката и изменения расписания нужны [права управления](user-guide.md#access-the-panel). На OpenWrt используйте [SSH-туннель](user-guide.md#ssh-tunnel).

Автоустановка по умолчанию выключена. Панель продолжает проверять наличие релизов. Чтобы устанавливать их автоматически, включите автообновление и сохраните время. Служба установит доступный релиз в указанную минуту по часам роутера, один раз в день при условии, что KeenProxy в это время работает. Во время установки служба ненадолго перезапускается.

Перед переходом с релизов Ordo Systems на релизы этого репозитория отключите автоустановку и сохраните локальные копии текущего бинарника и конфигурации. Запустите приведённый выше bootstrap по SSH с параметром `--version vX.Y.Z`, подставив тег, опубликованный в этом репозитории. Для установленной облегчённой сборки добавьте `--lite`. Следующие обновления из панели будут использовать релизы этого репозитория. Для отката между репозиториями сохраните пакет исходного релиза и соответствующую ему конфигурацию.

Установщик блокирует транзитный трафик до остановки старой службы. Сам роутер остаётся доступен из локальной сети. Блокировка снимается, когда перехват заработает в новой версии или в восстановленной после ошибки обновления. Если перехват не восстановится, блокировка останется. Чтобы вернуть доступ, запустите bootstrap из локальной сети с рабочим релизом и конфигурацией. Если включена маршрутизация IPv6, нужен рабочий `ip6tables`. На OpenWrt перед обновлением отключите программное и аппаратное ускорение потоков и перезагрузите firewall. Блокировка действует на трафик, проходящий через цепочки маршрутизации Netfilter на роутере.

В KeeneticOS с включённой маршрутизацией IPv6 для временного правила блокировки транзита нужен модуль Netfilter с условием `comment`. Если `ip6tables` сообщает `No chain/target/match by that name`, проверьте, что выполняется `ip6tables -t filter -S FORWARD`, и найдите `comment` в `/proc/net/ip6_tables_matches`. Если его нет, загрузите модуль из текущей прошивки в оболочке Entware под `root`.

```sh
module="/lib/modules/$(uname -r)/xt_comment.ko"
test -r "$module" && insmod "$module"
grep -Fx comment /proc/net/ip6_tables_matches
```

Когда `comment` появится в списке, повторно запустите bootstrap. После перезагрузки роутера проверьте наличие модуля ещё раз.

В режиме `management-only` панель может открываться, пока перехват трафика недоступен. Когда TPROXY блокирует запуск, проверьте готовность и повторите запуск с сохранённой конфигурацией из оболочки роутера. Если защищённый bootstrap оставил блокировку транзитного трафика, запустите его повторно с рабочим релизом и конфигурацией. [Повтор запуска после блокировки TPROXY](troubleshooting.md#retry-blocked-tproxy-startup)

**Откат** переустанавливает предыдущую опубликованную версию и выключает автоустановку. Для этого нужен доступ к GitHub. Конфиг сохраняется. Если конфиг несовместим, установщик сообщит об этом до перезапуска службы. Файл schema 2 старые релизы прочитать не могут: при откате установщик переключается на новейший сохранённый `config.v1*.yaml`, а новый файл оставляет как `config.v2*.yaml`. После чистой установки этого релиза резервной копии v1 нет, поэтому откат на более старый релиз отклоняется при проверке и ничего не меняет. Для следующего обновления воспользуйтесь установщиком из командной строки. См. [обновление с v0.10](troubleshooting.md#upgrade-from-v010).

## Первая настройка { #first-configuration }

1. В KeeneticOS войдите в роутер под учётной записью с правом управления. Откройте **Управление → Приложения → KeenProxy** или используйте адрес, который вывел установщик. На OpenWrt откройте в браузере `http://127.0.0.1:8086`, пока работает SSH-туннель. [Доступ и роли](user-guide.md#access-the-panel)
2. Вставьте ссылку на подписку. При нажатии **Проверить** KeenProxy отправит постоянный идентификатор устройства (HWID), отдельный для HTTPS-источника провайдера. Это может занять место в лимите устройств. Просмотрите результат, затем нажмите **Включить**, чтобы применить политику для обнаруженной домашней сети и сохранить `send_hwid: true` для будущих обновлений. В сообщении о лимите устройств или истечении подписки появится ссылка на личный кабинет, если провайдер передал её. [Первая и ручная настройка](user-guide.md#first-run)
3. На вкладке **Обзор** проверьте основное подключение. На вкладках **Маршрутизация** и **Устройства** настройте правила и доступ устройств. В **Подключениях** видны узлы подписки и свои профили. В **Диагностике** есть состояние службы, проверки, отчёты и обновления. [Страницы управления](user-guide.md#overview)
4. Проверьте нужный трафик с подключённого устройства. Если результат отличается от ожидаемого, откройте **Диагностику**. Успешная проверка HTTP подтверждает этот запрос. Для проблем с HTTPS или DNS проверьте их отдельно.

## Восстановление доступа { #recover-panel-access }

Если проверка сеанса KeeneticOS не проходит, откройте панель через SSH-туннель к loopback-адресу роутера. В KeeneticOS используйте SSH-сервер Entware, на OpenWrt — системный SSH-сервер. [Команда SSH и адрес панели](user-guide.md#ssh-tunnel)

Перед обновлением сохраните приватную копию конфигурации и доступ к предыдущему выпуску. [Установка и откат](#update-from-the-panel) · [Диагностика входа](troubleshooting.md#recover-access)

## Удаление

Выполните в оболочке Entware от имени root:

```sh
curl -fsSL https://raw.githubusercontent.com/LokiVPN/keen-proxy/master/tools/bootstrap.sh | /opt/bin/sh -s -- --uninstall
```

Команда остановит службу KeenProxy, созданную установщиком, и удалит `/opt/bin/keenproxy` и `/opt/etc/init.d/S99keenproxy`. Настройки в `/opt/etc/keenproxy/`, журналы и рабочие данные в `/opt/var/lib/keenproxy/` и ранее установленный внешний клиент TrustTunnel сохранятся. KeenProxy больше не использует этот исполняемый файл. При повторной установке KeenProxy подхватит сохранённые настройки.
