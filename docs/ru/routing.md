# Маршрутизация и DNS

Схемы перехвата, DNS и выбора маршрута собраны в разделе [«Как проходит трафик»](network-flow.md).

## Из чего состоит политика

| Элемент | Назначение |
| --- | --- |
| Соединение | Именованный туннель/прокси, доступный как целевой маршрут |
| Группа | Список доменов/адресов или выбор стран с маршрутом |
| Напрямую | Подключение без настроенного туннеля |
| Блокировать | Запрет подходящего трафика |
| Сеть | Политика по умолчанию для подсети |
| Клиент | Политика конкретного устройства по MAC-адресу |

Режим стран **Кроме** описывает трафик за пределами выбранных стран. Явные доменные списки и правила стран задают разные уровни политики; проверяйте журнал, чтобы узнать, какое правило сработало для конкретного запроса.

Переключатели соединений и правил меняют общий черновик; действующий трафик изменится после **Применить**. Отключённая группа, запись домена/IP, страна или категория пропускается с сохранением значения. Далее действуют подходящие правила и политика источника. Если все условия стран/категорий выключены, группа не действует даже в режиме **Кроме**.

## Правила по странам { #country-rules }

Группы стран сопоставляют **IP-адрес назначения** с базой GeoIP. Они не определяют гражданство пользователя, язык сайта или страну по доменному суффиксу. Выбор страны также не выбирает выходной сервер: маршрут отдельно задаётся в колонке **Соединение**.

### Всё, кроме России, через туннель

1. Создайте или импортируйте рабочее соединение, затем откройте **Правила → Белый список**.
2. Нажмите **По странам**. Новая группа создаётся с выбранной Россией (`RU`) и режимом **Все, кроме этих**. При необходимости нажмите на имя группы, чтобы переименовать её.
3. В колонке **Страны** оставьте `RU` или добавьте другие страны-исключения. Режим **Только эти страны** позволяет, наоборот, сопоставлять только выбранные страны.
4. В колонке **Соединение** выберите профиль, например **Finland WG**. **Напрямую** обходит туннель, **Блокировать** запрещает подходящий трафик.
5. Откройте **Соединения → Клиенты** и убедитесь, что нужная сеть или устройство использует режим **Раздельный**. Проверьте общий черновик и один раз нажмите **Применить**.

[![Группа стран: всё, кроме России, через Finland WG](../assets/screenshots/ru-countries.png)](../assets/screenshots/ru-countries.png)

Откройте список стран для поиска по названию или ISO-коду. Выбранные страны отображаются метками с кодами; удаление метки меняет черновик.

[![Русскоязычный выбор стран с выбранной Россией](../assets/screenshots/ru-country-picker.png)](../assets/screenshots/ru-country-picker.png)

### Какое правило побеждает

Глобальные блокирующие группы проверяются первыми. В маршрутизируемой политике устройства или сети явные группы доменов и адресов проверяются раньше групп стран. Настройки устройства приоритетнее настроек сети. Режим **Полный туннель** использует выбранное соединение по умолчанию и отличается от описанной здесь выборочной маршрутизации.

| Пример конфигурации | Результат |
| --- | --- |
| Домен Steam совпал с группой **Steam direct** | Напрямую, даже если IP назначения находится за пределами России |
| Домен совпал с группой **Video and social media** | Netherlands Reality, раньше общего правила по странам |
| Более ранних совпадений нет, IP назначения вне `RU` | Finland WG |
| Более ранних совпадений нет, IP назначения в `RU` | Правило стран-исключений не совпадает; выборочная политика использует прямой маршрут |

**Все, кроме этих** — инверсия условия, а не принудительный прямой маршрут для выбранных стран. Более раннее явное правило по-прежнему может направить российский адрес через другое соединение. Конкретные исключения задавайте группами доменов или адресов.

### Проверка результата

На реальной установке проверьте загрузку базы стран в **Диагностике**, примените конфигурацию и найдите выбранное соединение и сработавшее правило в **Журнале → Маршрутизация**. До загрузки GeoIP нельзя полагаться на правила стран. Адреса CDN и обновления базы могут менять страну IP; для важных исключений используйте явные домены или адреса.

## Базы стран

Группы по странам используют базы MMDB, которые настраиваются в разделе **Правила → Базы стран**. Порядок в списке — это приоритет: страну адреса определяет первая включённая база, которая его знает, и правила стран следуют тому же порядку. Встроенные источники можно включать, выключать и переставлять. Можно добавить свою базу: HTTPS-ссылку на `.mmdb`, `.mmdb.gz` или `.tar.gz` (`{month}` заменяется на `ГГГГ-ММ`, при отсутствии берётся прошлый месяц) либо абсолютный путь к файлу на роутере.

Роутер проверяет включённые базы раз в сутки. Файлы скачиваются только по HTTPS, сверяются с опубликованной суммой SHA-256, если источник её даёт, проверяются как база стран MMDB и подменяются атомарно. При ошибке прежний файл остаётся, повтор — через 10 минут, затем пауза удваивается до 6 часов. После изменения списка проверка начинается сразу после **Применить**.

Базы категорий — второй вид баз адресов. Вместо стран они помечают сети метками, например `RU-BLOCKED`, `RE-FILTER` или `TELEGRAM`, и в определении стран не участвуют. В группах метки выбираются в поле **Категории** — отдельно или вместе со странами и режимом **Все, кроме этих**. Включённые базы категорий объединяются: метка срабатывает, если её сообщает любая из них. Встроенные источники runetfreedom хранят у каждой сети только одну метку, поэтому сеть из нескольких исходных списков попадёт только в одну категорию. Для групп с категориями нужна хотя бы одна включённая база категорий.

## Резервные цепочки { #fallback-chains }

Соединение может ссылаться на другое соединение или прямой выход как непосредственный резерв. Интерфейс показывает получившуюся цепочку. Меняется ближайший резерв выбранного профиля; следующие унаследованные переходы принадлежат своим профилям. Избегайте циклов. Прямой выход в качестве резерва намеренно разрешает прямой маршрут при отказе основного.

Отключение соединения сохраняет ссылки из групп, клиентов, сетей и настроек DNS. Выключенные звенья цепочки пропускаются в пользу включённых настроенных резервов, но само ссылающееся правило не пропускается. Если включённых резервов нет, трафик блокируется; неявного перехода напрямую нет. Отключённый туннель или внешний клиент не запускается и не проверяется на доступность. Включите его и примените изменения для восстановления сохранённых настроек. DNS по-прежнему подчиняется отдельной политике strict/direct.

Периодическая проверка измеряет HTTP-запрос, а не ICMP-пинг. Она независима от ручных HTTPS-проверок и проверки передачи в Диагностике.

## Маршрут по умолчанию для раздельных политик { #default-route }

В режиме split трафик, не попавший ни в одну группу, идёт напрямую. Для сети можно задать `default`, чтобы направить такой трафик иначе: ID подключения или управляемая цель подписки пускает его в туннель, `direct` (или пусто) оставляет напрямую, а `profile` следует [правилам провайдера](#provider-rules): такой трафик идёт в цель политики, если применённый профиль провайдера не указывает `GlobalProxy: false` — тогда он идёт напрямую. Без правил провайдера `profile` тоже использует цель. `block` отклоняется; вместо него добавьте блокирующую группу. Устройства сети в режиме split наследуют её маршрут по умолчанию. Группы всегда приоритетнее маршрута по умолчанию.

```yaml
networks:
  - {name: Home, cidr: 192.168.7.0/24, mode: split, default: fi}
```

## Правила провайдера { #provider-rules }

`provider_rules` применяет правила маршрутизации, которые провайдер подписки присылает в профиле маршрутизации Happ. `source` — ID подписки. `disabled` — ключи правил, которые нужно выключить: `<действие>:<запись>`, например `block:geosite:category-ads`, либо `<действие>:literals:site` и `<действие>:literals:ip` для доменов и адресов, которые провайдер перечисляет сам.

```yaml
provider_rules:
  source: provider
  disabled: ["block:geosite:category-ads"]
```

Провайдер присылает профиль при каждой загрузке подписки: в заголовке ответа `routing` или, если заголовок пуст, строкой тела `happ://routing/add/<base64 JSON>` либо `happ://routing/onadd/<base64 JSON>`. Заголовок (или комментарий тела) `routing-enable` со значением, отличным от `true` и `1`, отключает правила, а `happ://routing/off` означает, что провайдер их не присылает. Профиль, который не удалось прочитать, показывается как ошибка с фиксированным текстом, а уже действующие правила остаются. KeenProxy применяет только списки самого профиля и не следит за обновлениями провайдера между загрузками подписки.

Каждая политика split, для сети или устройства, применяет правила после своих групп: сначала доменные правила провайдера в порядке `RouteOrder` из профиля (по умолчанию block, direct, proxy), затем резервное сопоставление доменов провайдера по DNS-наблюдению (см. ниже), затем его адресные правила в том же порядке, затем группы по странам и маршрут по умолчанию. Правила proxy используют цель самой политики, правила direct идут напрямую, правила block отклоняют соединение. Домен из двух списков следует списку, который идёт раньше в `RouteOrder`. Правила без данных провайдера и записи, которые sing-box не может использовать, пропускаются. Выключенные устройства и приостановленный роутер правила не затрагивают.

Записи используют синтаксис Xray. Доменные списки принимают `domain:` (суффикс), `full:`, `keyword:`, `regexp:`, `geosite:<категория>` (суффикс `@атрибут` допускается, используется вся категория) и простой текст, который считается ключевым словом. Адресные списки принимают IP и CIDR и `geoip:<тег>`. `geoip:private` и `geosite:private` пропускаются, потому что частные адреса всегда идут напрямую. Неподдерживаемые записи (`ext:`, `ext-domain:`, `dotless:`, категории с отрицанием `!`, неверные регулярные выражения, нечитаемые адреса) пропускаются и перечисляются в статусе правил, не более 50. Категория, файл данных которой отсутствует или не загрузился, показывается как недоступная и не маршрутизирует. Поле `GlobalProxy` профиля определяет только маршрут по умолчанию `profile`, а не эти правила.

Правила провайдера применяются только в описанном порядке. Если в профиле нет пригодных правил, политика работает как без правил провайдера, а `profile` по умолчанию использует цель сети.

Доменные правила провайдера действуют и на соединения без читаемого имени. Их адреса KeenProxy узнаёт только из DNS-ответов, которые устройства получают через него, и адрес следует правилу, пока не истечёт TTL ответа: в отличие от имён из ваших групп, имена провайдера KeenProxy в фоне не разрешает. В этом участвуют только доменные записи (`domain:`, `full:` и домены категорий geosite); ключевым словам и регулярным выражениям нужно читаемое имя.

Устройствам с политикой split KeenProxy сам отвечает адресом `0.0.0.0` на доменные имена из правил block провайдера, потому что их маршрутизация всё равно отклонила бы соединение. Имя, которое маршрутизация решает раньше, получает настоящий ответ: имя из ваших групп, которые не блокируют трафик, и имя, которое правило, идущее в `RouteOrder` раньше block, указывает как домен, точное имя или ключевое слово (регулярные выражения здесь не проверяются). Устройства в режиме полного туннеля получают настоящие ответы, потому что правила провайдера их трафик не маршрутизируют. Ваши блокирующие группы, как и раньше, блокируют для всех устройств.

### Файлы данных, лимиты и обновление { #provider-rules-data }

Категории берутся из файлов данных `Geositeurl` и `Geoipurl`, которые называет профиль. KeenProxy скачивает их напрямую (не через подключение), только по HTTPS, без переходов по редиректам, и извлекает только категории, на которые ссылается профиль. Профиль ограничен 256 КиБ после декодирования, каждый файл данных — 16 МиБ, данные geosite — 100 000 доменов, данные geoip — 200 000 префиксов суммарно; файл сверх лимита завершается фиксированным сообщением, а его правила остаются недоступными. У каждого файла таймаут загрузки одна минута. Профиль только с двухбуквенными тегами `geoip:` и без файла geoip использует встроенные базы стран.

Применение тратит на эти загрузки не более 20 секунд и останавливается за 15 секунд до собственного срока; если осталось меньше секунды, загрузки пропускаются. Правила без файла данных всё равно устанавливаются, а недостающие файлы скачиваются повторно в фоне через 1 минуту, затем 2, 4 и так далее до 1 часа, без повторной загрузки подписки. Данные неизменного файла используются повторно до одной недели.

Построенные правила и профиль, из которого они получены, сохраняются вместе со снимком подписки в каталоге состояния (приватно, режим 0600) и восстанавливаются при запуске до начала перехвата. Если обновление не удалось после построения полных правил, остаются прежние полные правила, а ошибка показывается; неполные правила заменяет успешная попытка. Отключение `provider_rules` освобождает их.

## Резерв для подписки { #subscription-reserve }

В подписке можно указать резерв через `fallback`: ID ручного подключения, `direct` или `block`. Для автоматической цели, если ни один узел не отвечает в течение `failover.down_after`, трафик идёт в резерв, а не остаётся на неработающем узле. Подключение со своей цепочкой отката сохраняет её, когда служит резервом. Трафик возвращается на узел, когда тот проходит проверки в течение `failover.up_after`. У режимов балансировки такой задержки нет: они следуют последней проверке каждого узла, поэтому используют резерв, как только последняя проверка не прошла ни у одного узла (в том числе сразу после запуска, до первой проверки), и возвращаются после первой успешной проверки. Закреплённый узел, исчезнувший из подписки, и подписка без узлов используют резерв сразу, без причины переключения. Без резерва автоматическая цель остаётся на последнем узле, а цели балансировки, закреплённые и пустые цели блокируют трафик. Статус подписки показывает резерв и причину переключения `fallback`, пока он используется. Подписка не может быть резервом другой подписки, а подключения не могут ссылаться на подписки.

```yaml
subscriptions:
  - {id: provider, url: "https://provider.example/links/example-token", fallback: home-wg}
```

## Пауза и выключенные устройства { #pause }

Устройство в режиме `off` KeenProxy не затрагивает: ни маршрутизации, ни блокировки, ни перехвата DNS, поэтому его DNS идёт прямо в резолвер KeeneticOS. Пауза роутера (`paused: true`) делает то же для всех устройств, пока демон продолжает работать; снятие паузы выполняется обычным применением. Перехват DNS и защита от шифрованного DNS действуют только на устройства, участвующие в политике сети или клиента.

```yaml
paused: true
```

## DNS

Настройки DNS определяют резолверы и маршрут запросов: напрямую или через соединение. Bootstrap-адреса помогают разрешать имена шифрованных DNS-серверов. Политика отказа задаёт, разрешён ли прямой DNS при проблемах выбранного пути. Списки фильтрации и исключения меняют DNS-ответы, а не все возможные виды трафика приложения.

Если KeenProxy использует резолвер в локальной сети, а тот пересылает запросы через этот же роутер на порт 53, роутер может вернуть запросы тому же резолверу. В разделе **Настройки → DNS → Дополнительные настройки** добавьте IPv4-адрес источника этого резолвера в исключения перехвата DNS и нажмите **Применить**. В YAML это `dns.bypass_sources`, например `bypass_sources: ["192.168.1.100"]` в секции `dns`. Назначьте резолверу статический адрес или зарезервируйте адрес в DHCP. Пустой список сохраняет прежнее поведение перехвата.

Исключение отправляет все запросы UDP/TCP на порт 53 с указанных адресов на настроенном LAN-интерфейсе в обход KeenProxy, в том числе его DNS-фильтрации. Оно не затрагивает других клиентов, маршрутизацию приложений на других портах и правила шифрованного DNS. Добавляйте только доверенные резолверы, которым нужно это исключение; правила пересылки самого роутера продолжают действовать.

Проверяйте перехват UDP/TCP и обработку шифрованного DNS на реальной тестовой сети роутера. Приложения могут использовать собственные резолверы. Интерфейс не доказывает универсальную защиту от DNS-утечек.

Скриншоты находятся в [руководстве](user-guide.md), объяснения результатов — в [диагностике и вопросах](troubleshooting.md).
