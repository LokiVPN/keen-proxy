# Маршрутизация и DNS

Схемы перехвата, DNS и выбора маршрута собраны в разделе [«Как проходит трафик»](network-flow.md).

## Вкладка «Маршрутизация» { #routing-tab }

Выберите режим для раздельной политики домашней сети и нажмите **Сохранить**.

В поле **Правила маршрутизации из подписки** выберите одну из настроенных подписок как источник правил. Кнопка **Проверить источник** показывает доступность правил выбранной подписки перед сохранением. Источник правил и основное подключение настраиваются отдельно. При сохранении другого источника переключатели правил прежней подписки сбрасываются.

- **По правилам подписки** применяет правила провайдера и указанный в профиле маршрут для остального трафика. Режим недоступен, если провайдер не передаёт правила. Правила в таблице сгруппированы по действию. Для отдельных записей в каждом списке сайтов и адресов есть общий переключатель. Для недоступных правил показана причина.
- **Весь трафик через VPN** направляет остальной трафик через основное подключение. Исключения можно добавить в список **Всегда напрямую**.
- **Только мои сайты** направляет остальной трафик напрямую. Сайты для основного подключения укажите в списке **Всегда через VPN**.

Оба списка видны в каждом режиме. В каждой строке укажите один домен, IP-адрес или подсеть. Домен включает свои поддомены. Свои списки важнее правил провайдера. Ошибка в строке или повтор записи в обоих редактируемых списках останавливает сохранение. Группы с особыми настройками доступны на этой вкладке для просмотра, а их записи не участвуют в проверке повторов. Выключенные правила останутся выключенными при возврате к режиму подписки с тем же источником. Если эта подписка не передаёт правила, можно редактировать свои списки, сохраняя уже выбранный режим. Если основное подключение направляет трафик напрямую или блокирует его, режим VPN недоступен. Если в подписке нет узлов для выбранной цели, доступность режима определяется [резервом](#subscription-reserve), который используется для этой цели. Дополнительные группы сохраняют маршруты и порядок, а политики устройств по-прежнему определяют, к каким устройствам применяются эти настройки.

## Из чего состоит политика

| Элемент | Назначение |
| --- | --- |
| Соединение | Именованный туннель/прокси, доступный как целевой маршрут |
| Группа | Список доменов/адресов или выбор стран с маршрутом |
| Напрямую | Подключение без настроенного туннеля |
| Блокировать | Запрет подходящего трафика |
| Сеть | Политика по умолчанию для подсети |
| Клиент | Политика конкретного устройства по MAC-адресу |

Условие `except: true` сопоставляет адреса за пределами перечисленных стран. Сработавшее правило можно проверить в журнале маршрутов.

Отключённая группа, запись домена/IP, страна или категория пропускается с сохранением значения. Далее действуют подходящие правила и политика источника. Если все условия стран и категорий выключены, группа не действует даже с `except: true`.

## Правила по странам { #country-rules }

Группы стран настраиваются в YAML. База GeoIP определяет страну IP-адреса назначения. Поле `target` группы указывает подключение, `direct` для прямого маршрута или `block` для блокировки.

### Всё, кроме России, через туннель

1. Создайте или импортируйте рабочее подключение на вкладке **Подключения**. Подставьте его ID вместо `fi`.
2. Добавьте группу и политику из примера в существующие секции `groups` и `networks`. Измените существующую запись домашней сети и подставьте её фактическую подсеть вместо примера CIDR. Если у устройства своя политика, проверьте, что в ней тоже задано `mode: split`.
3. Проверьте конфигурацию и перезапустите службу. [Изменение и загрузка YAML](user-guide.md#edit-and-reload-yaml)

```yaml
groups:
  - name: outside-ru
    target: fi
    countries: [RU]
    except: true
networks:
  - name: Home
    cidr: 192.0.2.0/24
    mode: split
    target: fi
    default: direct
```

Добавьте ISO-коды в `countries`, чтобы исключить из группы другие страны. С `except: false` группа сопоставляет перечисленные страны.

### Какое правило побеждает

Глобальные блокирующие группы проверяются первыми. В выборочном режиме явные группы доменов и адресов и действующие правила провайдера проверяются раньше групп стран. Настройки устройства приоритетнее настроек сети. В режиме полного туннеля выбранное подключение служит маршрутом по умолчанию.

| Пример конфигурации | Результат |
| --- | --- |
| Домен Steam совпал с группой **Steam direct** | Напрямую, даже если IP назначения находится за пределами России |
| Домен совпал с группой **Video and social media** | Netherlands Reality, раньше общего правила по странам |
| Более ранних совпадений нет, IP назначения вне `RU` | Finland WG |
| Более ранних совпадений нет, IP назначения в `RU` | Правило стран-исключений не совпадает; выборочная политика использует прямой маршрут |

Более раннее явное правило по-прежнему может направить российский адрес через другое подключение. Конкретные исключения задавайте группами доменов или адресов.

### Проверка результата

После перезапуска проверьте строку **База стран** в разделе **Диагностика → Состояние**. После загрузки базы проверьте с затронутого устройства назначения внутри и вне указанных стран. Посмотрите, какое правило сработало и какой маршрут выбран. Адреса CDN и обновления базы могут менять страну IP. Для узлов, которым нужен определённый маршрут, задайте явные домены или адреса. [Просмотр локальных журналов](troubleshooting.md#inspect-local-journals)

## Базы стран

Источники MMDB настраиваются в `geoip.databases` в YAML. Страну адреса определяет первая включённая база, в которой он есть. Меняйте порядок записей для настройки приоритета, а для отключения записи задайте `enabled: false`. Пример включает встроенную базу DB-IP. Для своей базы задайте уникальный `id`, `enabled: true` и поле `url` или `file`. Укажите HTTPS-ссылку на `.mmdb`, `.mmdb.gz` или `.tar.gz`. Вместо `{month}` подставляется год и месяц в формате `ГГГГ-ММ`, при отсутствии берётся прошлый месяц. Путь к файлу на роутере должен быть абсолютным. [Изменение и загрузка YAML](user-guide.md#edit-and-reload-yaml)

```yaml
geoip:
  databases:
    - id: dbip
      enabled: true
```

KeenProxy проверяет включённые базы при запуске и раз в сутки. Загруженные файлы сверяются с опубликованной суммой SHA-256, когда она доступна, проверяются как MMDB и заменяются атомарно. При ошибке прежний файл сохраняется, повтор выполняется через 10 минут, затем пауза удваивается до 6 часов. После перезапуска проверьте загрузку базы в разделе **Диагностика → Состояние**.

Базы категорий помечают сети метками, например `RU-BLOCKED`, `RE-FILTER` или `TELEGRAM`. Они проверяются отдельно от баз стран. Используйте `groups[].categories` отдельно или вместе с `countries`. Группа срабатывает при совпадении любого из условий, а `except: true` инвертирует этот общий результат. Для групп с категориями нужна хотя бы одна включённая база категорий. Метка совпадает, если её сообщает любая включённая база категорий. Встроенные источники runetfreedom назначают сети одну метку, даже если она есть в нескольких исходных списках.

## Резервные цепочки { #fallback-chains }

Соединение может ссылаться на другое соединение или прямой выход как непосредственный резерв. Интерфейс показывает получившуюся цепочку. Меняется ближайший резерв выбранного профиля; следующие унаследованные переходы принадлежат своим профилям. Избегайте циклов. Прямой выход в качестве резерва намеренно разрешает прямой маршрут при отказе основного.

При отключении подключения ссылки на него из групп, клиентов, сетей и настроек DNS сохраняются. Правило пропускает выключенные звенья цепочки и использует следующий включённый резерв. Если таких резервов нет, трафик блокируется. Отключённое подключение не запускается и не участвует в проверках доступности. Чтобы восстановить сохранённые настройки, откройте его на вкладке **Подключения**, установите **Включено** и нажмите **Сохранить**. Для DNS действует отдельная политика strict/direct.

Периодическая проверка измеряет HTTP-запрос, а не ICMP-пинг. Она независима от ручных HTTPS-проверок и проверки передачи в Диагностике.

## Маршрут по умолчанию для раздельных политик { #default-route }

В режиме split трафик, не попавший ни в одну группу, идёт напрямую. Для сети можно задать `default`, чтобы направить такой трафик иначе: ID подключения или управляемая цель подписки пускает его в туннель, `direct` (или пусто) оставляет напрямую, а `profile` следует [правилам провайдера](#provider-rules): такой трафик идёт в цель политики, если применённый профиль провайдера не указывает `GlobalProxy: false` — тогда он идёт напрямую. Без правил провайдера `profile` тоже использует цель. `block` отклоняется; вместо него добавьте блокирующую группу. Устройства сети в режиме split наследуют её маршрут по умолчанию. Группы всегда приоритетнее маршрута по умолчанию.

Трафик никогда не идёт напрямую только из-за того, что цель не задана. `profile` требует `target` сети, и сеть без неё отклоняется. Пока действуют правила провайдера, `target` нужен каждой сети в режиме split, потому что его используют правила proxy провайдера, и устройству в режиме split, если его адрес не входит в сеть с целью. Устройства с постоянным `ip` проверяются при сохранении конфигурации. Устройство, известное только по MAC-адресу, получает адрес во время работы и проверено быть не может, поэтому задайте ему собственный `target`, если оно может оказаться вне такой сети.

```yaml
networks:
  - {name: Home, cidr: 192.168.7.0/24, mode: split, default: fi}
```

## Правила провайдера { #provider-rules }

`provider_rules` применяет правила маршрутизации, которые провайдер подписки присылает в профиле маршрутизации Happ. `source` — ID подписки. `disabled` — ключи правил, которые нужно выключить: `<действие>:<запись>`, например `block:geosite:category-ads`, либо `<действие>:literals:site` и `<действие>:literals:ip` для доменов и адресов, которые провайдер перечисляет сам.

```yaml
provider_rules:
  source: provider
  disabled: ["block:geosite:category-ads"]
```

Укажите `off: true` в `provider_rules`, чтобы выключить все правила провайдера и сохранить `source` и `disabled`. Удалите этот параметр или задайте `off: false`, чтобы снова применить сохранённые переключатели. Пока правила выключены, маршрут по умолчанию `profile` использует цель политики. При удалении подписки-источника на вкладке **Подключения** удаляется и неактивный блок `provider_rules`, включая `disabled`.

Ключи `disabled` относятся к одному источнику. При смене `source` в YAML очистите `disabled`, чтобы сбросить переключатели прежней подписки. При сохранении другого источника в панели они сбрасываются автоматически.

Категории с приватными данными подписки получают непрозрачный ключ переключателя. Ранее сохранённые ключи продолжают управлять соответствующими правилами.

Провайдер присылает профиль при каждой загрузке подписки: в заголовке ответа `routing` или, если заголовок пуст, строкой тела `happ://routing/add/<base64 JSON>` либо `happ://routing/onadd/<base64 JSON>`. Заголовок (или комментарий тела) `routing-enable` со значением, отличным от `true` и `1`, отключает правила, а `happ://routing/off` означает, что провайдер их не присылает. Если KeenProxy не удаётся прочитать обновлённый профиль, уже действующий полный набор правил сохраняется. KeenProxy применяет только списки самого профиля и не следит за обновлениями провайдера между загрузками подписки.

Каждая политика split, для сети или устройства, применяет правила после своих групп: сначала доменные правила провайдера в порядке `RouteOrder` из профиля (по умолчанию block, direct, proxy), затем резервное сопоставление доменов провайдера по DNS-наблюдению (см. ниже), затем его адресные правила в том же порядке, затем группы по странам и маршрут по умолчанию. Правила proxy используют цель самой политики (политике split она нужна, см. [маршрут по умолчанию](#default-route)), правила direct идут напрямую, правила block отклоняют соединение. Домен из двух списков следует списку, который идёт раньше в `RouteOrder`. Правила без данных провайдера и записи, которые sing-box не может использовать, пропускаются. Выключенные устройства и приостановленный роутер правила не затрагивают.

Записи используют синтаксис Xray. Доменные списки принимают `domain:` (суффикс), `full:`, `keyword:`, `regexp:`, `geosite:<категория>` (с суффиксом `@атрибут` — только домены категории с этим атрибутом) и простой текст, который считается ключевым словом. Адресные списки принимают IP и CIDR и `geoip:<тег>`. `geoip:private` и `geosite:private` пропускаются, потому что частные адреса всегда идут напрямую. Неподдерживаемые записи пропускаются. К ним относятся `ext:`, `ext-domain:`, `dotless:`, категории с отрицанием `!`, неверные регулярные выражения, нечитаемые адреса и записи `geosite:` или `geoip:` длиннее 249 байт с учётом префикса. На вкладке «Маршрутизация» видны доступные группы правил и причина рядом с недоступными категориями. Вкладка «Подключения» показывает общее состояние правил подписки. Поле `GlobalProxy` профиля определяет только маршрут по умолчанию `profile`, а не эти правила.

Из обработанного профиля берётся маршрут по умолчанию `GlobalProxy`, даже если в нём нет пригодных правил. Если профиль не применяется, `default: profile` использует цель политики.

Доменные правила провайдера действуют и на соединения без читаемого имени. Их адреса KeenProxy узнаёт только из DNS-ответов, которые устройства получают через него, и адрес следует правилу, пока не истечёт TTL ответа: в отличие от имён из ваших групп, имена провайдера KeenProxy в фоне не разрешает. В этом участвуют только доменные записи (`domain:`, `full:` и домены категорий geosite); ключевым словам и регулярным выражениям нужно читаемое имя. Эти адреса делят с вашими группами кэш на 4096 имён, и при его заполнении первыми вытесняются имена провайдера.

Устройствам с политикой split KeenProxy сам отвечает адресом `0.0.0.0` на доменные имена из правил block провайдера, потому что их маршрутизация всё равно отклонила бы соединение. Имя, которое маршрутизация решает раньше, получает настоящий ответ: имя из ваших групп, которые не блокируют трафик, и имя, которое правило, идущее в `RouteOrder` раньше block, указывает как домен, точное имя или ключевое слово (регулярные выражения здесь не проверяются). Устройства в режиме полного туннеля получают настоящие ответы, потому что правила провайдера их трафик не маршрутизируют. Ваши блокирующие группы, как и раньше, блокируют для всех устройств.

### Файлы данных, лимиты и обновление { #provider-rules-data }

Категории берутся из файлов данных `Geositeurl` и `Geoipurl`, которые называет профиль. KeenProxy скачивает их напрямую (не через подключение), только по HTTPS, следуя не более чем трём HTTPS-редиректам (например, с релизной загрузки) и никогда не покидая HTTPS, и извлекает только категории, на которые ссылается профиль. Для загрузок и редиректов KeenProxy при подключении отклоняет адреса loopback, частные адреса (RFC 1918 и IPv6 ULA), адреса link-local, неуказанные и групповые адреса, в том числе когда имя хоста разрешается в такой адрес. Профиль ограничен 256 КиБ после декодирования, каждый файл данных — 16 МиБ, данные geosite — 100 000 доменов, данные geoip — 200 000 префиксов суммарно; файл сверх лимита завершается фиксированным сообщением, а его правила остаются недоступными. У каждого файла таймаут загрузки одна минута. Профиль только с двухбуквенными тегами `geoip:` и без файла geoip использует встроенные базы стран.

Применение тратит на эти загрузки не более 20 секунд и останавливается за 15 секунд до собственного срока; если осталось меньше секунды, загрузки пропускаются. Правила без файла данных всё равно устанавливаются, а недостающие файлы скачиваются повторно в фоне через 1 минуту, затем 2, 4 и так далее до 1 часа, без повторной загрузки подписки. Данные неизменного файла используются повторно до одной недели.

Построенные правила и профиль, из которого они получены, сохраняются вместе со снимком подписки в каталоге состояния (приватно, режим 0600) и восстанавливаются при запуске до начала перехвата. Для подписок с отправкой HWID KeenProxy восстанавливает сохранённый текст провайдера и правила, только когда текущий идентификатор установки совпадает с использованным при получении подписки. Если совпадение не подтверждено, правила обрабатываются заново при следующем получении подписки. Если провайдер не передаёт правила, можно сохранить уже выбранный режим подписки. Для перехода в этот режим нужен ответ провайдера с правилами. Если обновление не удалось после построения полных правил для того же идентификатора, прежние правила продолжают действовать. Успешная попытка заменяет неполные правила. Отключение `provider_rules` освобождает их.

## Резерв для подписки { #subscription-reserve }

В подписке можно указать резерв через `fallback`: ID ручного подключения, `direct` или `block`. Для автоматической цели, если ни один узел не отвечает в течение `failover.down_after`, трафик идёт в резерв, а не остаётся на неработающем узле. Подключение со своей цепочкой отката сохраняет её, когда служит резервом. Трафик возвращается на узел, когда тот проходит проверки в течение `failover.up_after`. У режимов балансировки такой задержки нет: они следуют последней проверке каждого узла, поэтому используют резерв, как только последняя проверка не прошла ни у одного узла (в том числе сразу после запуска, до первой проверки), и возвращаются после первой успешной проверки. Закреплённый узел, исчезнувший из подписки, и подписка без узлов используют резерв сразу, без причины переключения. Без резерва автоматическая цель остаётся на последнем узле, а цели балансировки, закреплённые и пустые цели блокируют трафик. Статус подписки показывает резерв и причину переключения `fallback`, пока он используется. Подписка не может быть резервом другой подписки, а подключения не могут ссылаться на подписки.

```yaml
subscriptions:
  - {id: provider, url: "https://provider.example/links/example-token", fallback: home-wg}
```

## Пауза и выключенные устройства { #pause }

Устройство в режиме `off` использует обычную маршрутизацию и DNS роутера. Выключение KeenProxy переключателем на вкладке **Обзор** (`paused: true`) действует так же для всех устройств, а служба продолжает работать. Включите KeenProxy снова, чтобы возобновить маршрутизацию. Перехват DNS и защита от шифрованного DNS действуют только на устройства, участвующие в политике сети или клиента.

```yaml
paused: true
```

## DNS

Секция `dns` в YAML определяет резолверы и маршрут запросов напрямую или через подключение. Bootstrap-адреса помогают разрешать имена шифрованных DNS-серверов. Политика отказа определяет, разрешён ли прямой DNS при сбое выбранного маршрута.

Если локальный резолвер, который использует KeenProxy, пересылает запросы через этот же роутер на порт 53, перехват может вернуть запросы резолверу. Назначьте резолверу статический IPv4-адрес или зарезервируйте адрес в DHCP. Добавьте IPv4-адрес источника в `dns.bypass_sources` в существующей секции `dns`, подставив его вместо адреса из примера. Проверьте конфигурацию и перезапустите службу. Пустой список оставляет перехват в обычном режиме. [Изменение и загрузка YAML](user-guide.md#edit-and-reload-yaml)

```yaml
dns:
  bypass_sources: ["192.0.2.53"]
```

Запросы с указанных адресов на порт 53 по UDP и TCP на настроенном LAN-интерфейсе обходят KeenProxy и его DNS-фильтрацию. Для других клиентов, портов приложений и правил шифрованного DNS действуют заданные политики. Добавляйте только доверенные резолверы, которым нужно это исключение. Правила пересылки самого роутера продолжают действовать.

После перезапуска проверьте состояние DNS в **Диагностике**. Выполните DNS-запросы по UDP и TCP с резолвера и с участвующего клиента. Убедитесь, что резолвер обращается к своему вышестоящему серверу без зацикливания, а клиент по-прежнему использует заданную политику DNS. [Диагностика неполадок](troubleshooting.md)
