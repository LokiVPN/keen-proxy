# Руководство пользователя

## Как открыть панель { #access-the-panel }

1. Из локальной сети войдите в веб-интерфейс KeeneticOS в том же браузере, где будете открывать KeenProxy.
2. Перейдите в **Управление → Приложения** и нажмите **Открыть панель** на карточке KeenProxy. Если карточки нет, используйте адрес, который вывел установщик. Его можно посмотреть снова командой `keenproxy --url`. По умолчанию панель работает на порту `8086`.
3. Откройте панель на том же имени или IP-адресе, по которому вы вошли в KeeneticOS. Для входа по адресу роутера откройте `http://ROUTER_LAN_IP:8086`. Если вы вошли через `my.keenetic.net`, откройте карточку или `http://my.keenetic.net:8086`.

| Учётная запись роутера | Доступ |
| --- | --- |
| Администратор с доступом к веб-интерфейсу и CLI | Управляет настройками, запускает проверки, скачивает отчёты, управляет обновлениями. |
| Учётная запись только для чтения или менеджер с доступом к веб-интерфейсу | Просматривает страницы и состояние. Настройки и действия управления недоступны, учётные данные подключений скрыты. |
| Другие учётные записи | KeenProxy показывает **Нет доступа**. |

Если сеанс истёк, нажмите **Войти в KeeneticOS** и снова откройте KeenProxy. Кнопка **Выйти** завершает сеанс роутера. KeenProxy выбирает русский или английский по языку браузера, а светлую или тёмную тему по настройкам системы. На телефоне прокрутите строку вкладок вбок, чтобы увидеть все пять.

Если проверка сеанса недоступна или KeenProxy работает на OpenWrt, воспользуйтесь [SSH-туннелем](#ssh-tunnel).

<a name="first-run"></a>

## Первая настройка { #first-run }

1. Откройте KeenProxy под учётной записью с правом управления. При первой настройке панель попросит ссылку на подписку.
2. Вставьте HTTPS-ссылку из личного кабинета LokiVPN и нажмите **Проверить**. При проверке провайдер получает постоянный идентификатор устройства (HWID), отдельный для его HTTPS-источника. Это может занять место в лимите устройств. Просмотрите список серверов и сведения, которые передал провайдер, включая срок действия, расход трафика, правила и сообщение. Если достигнут лимит, удалите неиспользуемое устройство в личном кабинете. Если подписка истекла, продлите её. Затем проверьте ссылку снова.
3. Нажмите **Включить**, чтобы сохранить подписку и настроить выборочную маршрутизацию для обнаруженной домашней сети. При этом сохраняется `send_hwid: true`: при последующих обновлениях KeenProxy будет отправлять идентификатор. KeenProxy использует профиль провайдера, если он доступен. Если профиля нет, трафик без подходящего правила идёт через подписку. Для первой настройки нужен частный IPv4-адрес на выбранном LAN-интерфейсе.
4. На вкладке **Обзор** проверьте выбранное подключение, а на вкладке **Устройства** выберите, кто будет его использовать. Проверьте нужный сайт с одного из этих устройств.

Чтобы добавить подписку к существующей конфигурации, откройте **Обзор → Настроить подписку**, нажмите **Проверить**, затем **Добавить подписку**. Для обновления ссылки откройте **Обзор → Заменить ссылку**, нажмите **Проверить**, затем подтвердите замену кнопкой **Заменить ссылку**. В обоих случаях **Проверить** отправляет провайдеру постоянный HWID ещё до сохранения и может занять место в лимите устройств. При подтверждении сохраняется `send_hwid: true` для будущих обновлений. При замене ссылки отправка HWID включается, даже если раньше было `false`. ID подписки, резерв, настройки маршрутизации и устройств сохраняются.

Чтобы заменить ссылку с отключённой отправкой HWID, измените `url` этой подписки в YAML и сохраните `send_hwid: false`. [Изменение и загрузка YAML](#edit-and-reload-yaml)

Для ручной настройки откройте [Подключения](#connections). Со страницы первой настройки туда можно перейти, добавив `/connections` к адресу панели. Добавьте подключение. Если политики домашней сети ещё нет, задайте её в [YAML](#configuration-and-backups). Затем выберите подключение на вкладке **Обзор**.

<a name="overview"></a>

## Обзор { #overview }

- Переключатель **Включено** приостанавливает или возобновляет маршрутизацию для всей сети. Во время паузы устройства используют обычный доступ в интернет. В списке **Основное подключение** доступны автоматический выбор, балансировка, конкретный узел подписки и свои подключения. Оба изменения применяются сразу. Если JavaScript отключён, нажмите **Сохранить** рядом с нужным полем.
- Строка состояния называет активное подключение или резерв и сообщает о недоступности маршрута. Она учитывает устройства с сохранённой маршрутизацией, даже если новые устройства по умолчанию подключаются напрямую. Когда эти устройства используют разные подключения, в обзоре указана маршрутизация по устройствам. В разделе **Подписка** видны срок действия и трафик, если их передал провайдер, а также время последнего и следующего обновления. **Обновить сейчас** ставит в очередь обновление показанной подписки.
- График **Трафик через VPN** охватывает последние 30 минут. Для группы sing-box, в которой есть прямые соединения и туннели, он может включать прямой трафик группы. Сводки по устройствам и маршрутизации ведут на соответствующие вкладки.

<a name="routing"></a>

## Маршрутизация { #routing }

Выберите режим и нажмите **Сохранить**.

- **По правилам подписки** использует правила провайдера и его маршрут по умолчанию. Просмотрите разделы **Через VPN**, **Напрямую** и **Блокировать**. При необходимости отключите отдельные правила. Выключенное правило остаётся выключенным после обновления подписки. Панель поясняет, когда правила загружаются, отсутствуют или недоступны. Если провайдер перестал присылать правила, можно сохранить свои списки сайтов в уже выбранном режиме подписки.
- **Весь трафик через VPN** использует основное подключение для трафика за пределами домашней сети с учётом ваших исключений. Если основное подключение может использовать прямой маршрут и туннель, в названии режима указано подключение. Панель также показывает активный резерв, если он известен.
- **Только свои сайты** отправляет сайты из списка через основное подключение, а трафик без подходящего правила — напрямую.

В разделе **Свои сайты** вводите по одному домену, IP-адресу или подсети на строку. Запись домена учитывает его поддомены. Добавляйте исключения в список **Всегда напрямую** и заносите каждый адрес только в один список. Сложные группы маршрутизации и DNS настраиваются в YAML. [Маршрутизация и DNS](routing.md)

Если провайдер перестал передавать правила, пока вы меняли переключатели, дождитесь возвращения правил и сохраните изменения переключателей. Изменения в своих списках можно сохранить отдельно.

<a name="devices"></a>

## Устройства { #devices }

KeenProxy показывает обнаруженные в LAN устройства и устройства из конфигурации, включая сохранённые, но отключённые от сети. Включайте и выключайте VPN для отдельных устройств или используйте **Включить всем** и **Выключить всем**. Если для устройства нет подходящего маршрута VPN, проверьте подсказку в его строке. Устройство с сохранённым переключателем VPN и неизвестным IP ждёт адреса. Если после смены адреса для включённого устройства не осталось цели VPN, проверьте его строку перед повторным сохранением.

Настройка **Новые устройства сразу используют VPN** задаёт политику для новых устройств домашней сети. При её изменении переключатели для уже показанных устройств сохраняют своё положение. Нажмите **Сохранить**, чтобы применить список и политику по умолчанию. **Отменить** возвращает сохранённые настройки.

<a name="connections"></a>

## Подключения { #connections }

### Подписки { #native-subscriptions }

В разделе подписки видны узлы, последние результаты их HTTPS-проверок и сообщения о правилах. Нажмите **Обновить сейчас** для этой подписки, **Проверить** для одного узла или **Проверить все узлы** для всего списка. Проверки подтверждают сертификат сервера. Эти действия оставляют подготовленные изменения в форме. Чтобы применить резерв или переключатель своего подключения, нажмите **Сохранить**.

В поле **Резерв, если не отвечает ни один узел** выберите своё подключение, **Напрямую — без VPN** или **Нет — блокировать VPN-трафик**. Если своё резервное подключение недоступно или выключено, дальнейший маршрут определяет его собственная цепочка резервирования. **Резерв не задан** сохраняет отсутствие резерва. [Резервы подписки](routing.md#subscription-reserve)

В списке **Основное подключение** на вкладке **Обзор** режим **Авто — при сбое на другой узел** следует порядку провайдера и остаётся на рабочем узле после переключения. Метка **Текущий** обозначает выбранный узел и может отображаться одновременно с **Недоступен** после неудачной проверки. Закреплённый узел остаётся выбранным и использует настроенный резерв, если исчезает из подписки. Режимы **Балансировка: по очереди**, **по сайту** и **по сессии** распределяют новые соединения между подходящими узлами. [Выбор узла и балансировка](routing.md#subscription-reserve)

KeenProxy принимает HTTPS-списки ссылок Xray в обычном тексте или Base64, до 2 МиБ и 256 разных узлов. Если обновление не удалось, панель показывает его состояние, а KeenProxy сохраняет последний проверенный список. Храните ссылки подписки в секрете. Если имя узла повторяет его собственные учётные данные, панель показывает номер узла.

### Добавление и замена своего подключения { #manual-connections }

1. Нажмите **Добавить подключение**. На вкладке **Вставить** принимаются ссылка подключения, самостоятельный клиентский экспорт Amnezia `vpn://`, текст WireGuard или AmneziaWG `.conf` и один outbound или endpoint sing-box в JSON. Вариант **Из файла** принимает те же форматы до 2 МиБ. Вариант **Вручную** поддерживает WireGuard, VLESS, Shadowsocks, Trojan, Hysteria2 и SOCKS.
2. Нажмите **Проверить** и просмотрите тип, сервер и другие параметры. Учётные данные на этом шаге скрыты. Если в экспорте есть несколько поддерживаемых профилей, выберите один. В самостоятельном JSON-профиле sing-box уберите ссылки на маршруты, например `detour` и `domain_resolver`.
3. Для нового подключения проверьте предложенные имя и идентификатор и нажмите **Сохранить**. Уникальный идентификатор длиной до 32 символов начинается со строчной латинской буквы или цифры и может содержать строчные латинские буквы, цифры, дефисы и подчёркивания. Если срок проверки истёк или настройки роутера изменились, проверьте профиль заново перед сохранением.

Откройте своё подключение по имени. Задайте **Включено** и **Резерв**, затем нажмите **Сохранить**. Кнопка **Проверить** проверяет сохранённый включённый профиль без применения несохранённых правок. Страница показывает цепочку резервирования, скорость и трафик по сайтам, когда эти данные доступны. Для групп sing-box она даёт ссылки на подключения, через которые идёт трафик.

Нажимайте **Показать параметры**, когда нужно вывести учётные данные на экран. **Заменить параметры** открывает мастер для того же идентификатора. Замена сохраняет существующие ссылки на подключение. При удалении панель перечисляет ссылки, которые нужно убрать. Выключенное подключение сохраняет учётные данные и ссылки на него, пока трафик идёт по настроенным резервам. Если включённых резервов нет, трафик для этого подключения блокируется. [Цепочки резервирования](routing.md#fallback-chains)

<a name="diagnostics"></a>

## Диагностика { #diagnostics }

- Проверьте состояние ядра, перехвата, DNS, конфигурации, базы стран, сторожа фаервола и нагрузку. Для нового снимка состояния воспользуйтесь ссылкой обновления.
- Кнопка **Запустить проверку** измеряет отдельно HTTP, HTTPS с проверкой сертификата и передачу 64 КиБ. Проверка использует текущий основной маршрут VPN и сама не переключает его на резерв. Если выбранный маршрут подписки использует резерв или блокирует трафик, отчёт указывает этот маршрут и пропускает измерения VPN. Это касается автоматического выбора, балансировки без подходящих TCP-узлов и исчезнувшего закреплённого узла. KeenProxy также сообщает, если маршрутизация остановлена или приостановлена. Прежде чем считать проблему решённой, проверьте нужное приложение с устройства.
- В разделе **Отчёт для поддержки** под учётной записью с правом управления нажмите **Скачать ZIP**. В архиве есть состояние, сведения о сборке и последние ошибки. Проверьте архив перед отправкой. Кнопка **Скопировать** копирует сведения о сборке. [Содержимое диагностического ZIP](troubleshooting.md#download-the-diagnostic-zip)
- В разделе **Обновления** проверьте наличие релиза, установите его или откатитесь на записанную предыдущую версию. Подтвердите версию и дождитесь запуска службы. Если включили **Устанавливать автоматически**, сохраните время по часовому поясу роутера. [Условия обновления и отката](getting-started.md#update-from-the-panel)

## Сохранение изменений { #save-changes }

Формы на вкладках **Маршрутизация**, **Устройства** и в настройках подключений применяют изменения по кнопке **Сохранить**. На вкладке **Обзор** главный переключатель и выбор основного подключения применяются сразу. Если настройки уже изменились в другом окне, проверьте текущие значения и сохраните их снова. KeenProxy отклоняет устаревшую форму.

## Восстановление доступа через SSH { #ssh-tunnel }

С компьютера в локальной сети пробросьте локальный порт к loopback-адресу панели на роутере. Замените `ROUTER` именем SSH-сервера или LAN-адресом роутера. В примере используются SSH-порт Entware и стандартный порт панели.

```sh
ssh -N -p 222 -L 127.0.0.1:8086:127.0.0.1:8086 root@ROUTER
```

На OpenWrt уберите `-p 222`, если SSH использует стандартный порт. Оставьте туннель работающим и откройте `http://127.0.0.1:8086`. Через туннель обращение по loopback-адресу даёт права управления. Панель на роутере должна принимать соединения на loopback. Если её порт отличается, укажите его в правой части проброса. [Восстановление входа и настройка службы](troubleshooting.md#recover-access)

## Конфигурация и резервные копии { #configuration-and-backups }

В Entware конфигурация хранится в `/opt/etc/keenproxy/config.yaml`, в нативной установке OpenWrt — в `/etc/keenproxy/config.yaml`. Сохраните приватную копию перед изменением DNS, интерфейсов, адреса прослушивания или сложных правил. В файле есть ссылки подписок и учётные данные подключений. KeenProxy читает его при запуске службы. [Пути установки и команды службы](getting-started.md) · [Управляющий API на loopback](development.md#control-api)

### Изменение и загрузка YAML { #edit-and-reload-yaml }

1. В оболочке SSH роутера сохраните приватную резервную копию и отредактируйте копию рабочей конфигурации. Добавляйте значения из примеров в соответствующие существующие разделы.
2. Выполните на роутере `keenproxy -dry-run -config /path/to/candidate.yaml`. Храните вывод приватно: в нём могут быть учётные данные. Прежде чем продолжать, исправьте ошибки или причину предупреждения `configuration would be reset after upgrade`.
3. Поместите проверенный файл по пути рабочей конфигурации, сохранив его права доступа. Перезапустите службу командой `/opt/etc/init.d/S99keenproxy restart` в Entware или `/etc/init.d/keenproxy restart` в нативном OpenWrt.
4. Проверьте состояние службы в **Диагностике** и нужный трафик с устройства. Если служба не запустилась или проверка трафика не прошла, верните резервную копию и снова перезапустите службу.

### Мягкий лимит памяти { #soft-memory-limit }

Ключ YAML `system.memory_limit_mib` задаёт мягкий лимит Go для KeenProxy и встроенного ядра. Укажите целое положительное значение в МиБ. Более низкий лимит может участить сборку мусора и снизить скорость. Оставляйте запас для прошивки и других служб. [Руководство Go по лимиту памяти](https://go.dev/doc/gc-guide#Memory_limit)

```yaml
system:
  memory_limit_mib: 400
```

Без ключа KeenProxy использует унаследованный лимит Go, включая `GOMEMLIMIT=off`. Если унаследованного лимита нет, используется 768 МиБ. Процесс может превысить эту рекомендацию по памяти, она не ограничивает RSS.

## Совместимость подключений { #connection-compatibility }

### Профили AmneziaWG (экспериментальная сборка lx)

Импортируйте однопировый `.conf` AmneziaWG или вставьте его содержимое в мастер подключений. При наличии AWG-полей автоматически выбирается **AmneziaWG**. При сохранении подключения KeenProxy сохраняет исходный профиль. Храните файл приватно, поскольку внутри есть закрытый ключ туннеля и может быть предварительно согласованный ключ.

Эта сборка использует [sing-box-lx 1.14.4-lx.35](https://github.com/Leadaxe/sing-box-lx/releases/tag/v1.14.4-lx.35). Поддерживаются клиентские параметры AWG 2/3 и TCP/UDP приложений через userspace-endpoint WireGuard; внешний туннель использует UDP. Модуль AWG в ядре и отдельный демон не нужны. Неподдерживаемые поля, исполняемые команды и несколько пиров отклоняются, а не теряются при импорте.

Для автономного клиентского экспорта Amnezia `vpn://` вставьте ссылку целиком или загрузите текстовый файл либо `.vpn` со ссылкой. KeenProxy декодирует экспорт локально. Если внутри несколько AWG-профилей, выберите один и снова нажмите **Проверить**. Проверьте название и идентификатор, затем сохраните выбранную клиентскую конфигурацию AWG.

Поддерживаются сжатые и несжатые автономные экспорты с допустимой версией формата (отсутствует, 0 или 1). Размер закодированной ссылки ограничен 2 МиБ, декодированного JSON — 1 МиБ. В одном экспорте допускается не более 32 кандидатов AWG и не более 1 МиБ нативных профилей суммарно; при превышении лимита экспорт отклоняется целиком, без частичного импорта. Повреждённые экспорты, неподдерживаемые параметры протокола, ключи сервиса/подписки и административные экспорты без клиентских ключей отклоняются. Ссылка `vpn://` не обязательно содержит готовый туннель: нужен **экспорт клиентского подключения**, а не ключ активации подписки.

Для ограничения расхода памяти роутера junk-серия ограничена 256 пакетами и 1 МиБ полезной нагрузки на одно рукопожатие в худшем случае. Ограничение действует для нативных профилей AWG и raw-endpoint WireGuard после декодирования параметров ядром.

Поле `DNS` профиля не заменяет настройки DNS KeenProxy. Соединение по-прежнему выбирают существующие правила и failover; `AllowedIPs` не устанавливает системные маршруты. Для UDP приложений нужен перехват **TPROXY**. Существующее **отклонение UDP/443 участвующих клиентов сохраняется**: импорт AWG не включает клиентский QUIC. Активация подписок Amnezia, настройка серверов и интеграция с API сервиса не поддерживаются.

В YAML сохраните профиль многострочной строкой:

```yaml
connections:
  - id: awg
    name: AmneziaWG
    type: amneziawg
    amneziawg: |
      [Interface]
      PrivateKey = <client-private-key-base64>
      Address = 10.77.0.2/32
      Jc = 3
      Jmin = 40
      Jmax = 80
      S1 = 20
      S2 = 30
      H1 = 1001
      H2 = 1002
      H3 = 1003
      H4 = 1004
      [Peer]
      PublicKey = <server-public-key-base64>
      Endpoint = vpn.example.com:51820
      AllowedIPs = 0.0.0.0/0
```

Замените заполнители и параметры обфускации значениями из экспорта своего сервера. Перед откатом на сборку с официальным sing-box удалите или замените подключения AmneziaWG и сохраните конфигурацию, чтобы её мог загрузить старый движок.

### Совместимость sing-box-lx { #sing-box-lx-compatibility }

Обе сборки поддерживают XHTTP и встроенный TrustTunnel наряду с существующими VLESS, REALITY и AWG. Вставьте экспортированную сервером ссылку или один готовый sing-box outbound в мастер подключений. Нажмите **Проверить**, просмотрите профиль и нажмите **Сохранить**, чтобы применить его.

Ссылки VLESS сохраняют параметр `encryption`, а не отбрасывают его. Гибридный обмен ключами REALITY и шифрование VLESS — разные механизмы; ни один не добавляет поддержку подписей Xray `pqv` или `spiderX`. Используйте параметры своего сервера, а не включайте шифрование произвольно.

Поддерживаемые параметры ссылок:

| Возможность | Параметры |
| --- | --- |
| XHTTP | `type=xhttp` или `splithttp`, `host`, `path`, `mode=auto/packet-up/stream-up/stream-one`, URL-кодированный JSON `extra` и `xmux` |
| Шифрование VLESS | `encryption=mlkem768x25519plus.…`; `none` отключает этот слой |
| REALITY | `key_share=hybrid` или `classical` (алиас `keyShare`), вместе с `pbk`, `sid`, `sni` и `fp` |
| Фрагментация TLS | Явные булевы значения `fragment`, `record_fragment` (алиас `recordFragment`) и длительность `fragment_fallback_delay` (алиас `fragmentFallbackDelay`) |

Некорректные флаги, неподдерживаемые опции XHTTP, непустые `pqv`/`fm` и нестандартные значения `spx` отклоняются при импорте. Для опций движка без преобразования из ссылки остаётся готовый sing-box JSON; при применении его проверяет движок.

Для XHTTP (`type=xhttp` или `splithttp`) с `flow=xtls-rprx-vision` нужен включённый слой VLESS `encryption`. Ссылки с таким сочетанием без encryption или с `encryption=none` отклоняются при импорте; одного TLS/REALITY недостаточно. Профили XHTTP/Vision с включённым шифрованием остаются поддерживаемыми.

Полная сборка включает QUIC/HTTP/3. Lite сохраняет TCP/TLS-транспорты, в том числе XHTTP через HTTP/1.1 или HTTP/2 и TrustTunnel через HTTP/2; профили только с HTTP/3 требуют полной сборки. Этот выбор транспорта движка не меняет политику перехвата клиентского UDP/443.

TrustTunnel использует `type: link` и полную экспортированную ссылку `tt://?…`. Старые секции `type: trusttunnel` преобразуются при загрузке и записываются как ссылки при следующем сохранении конфигурации. Поля `binary` и `socks_port` больше не управляют отдельным процессом. Ранее установленные внешние клиенты не удаляются, но больше не используются. Перед миграцией сохраните старый конфиг, если нужен откат на сборку с внешним клиентом.

Обновление и `--uninstall` оставляют старые файлы `bin/trusttunnel_client` и `share/keenproxy/trusttunnel/` внутри каталога установки (обычно `/opt`). Убедившись, что встроенное соединение работает, удалите их вручную, только если они не используются другими сервисами и больше не нужны для отката на внешний клиент. Сначала сохраните старую конфигурацию; сгенерированные файлы клиента могут содержать реквизиты доступа.

API состояния больше не возвращает поле `trusttunnel` со статусом внешнего процесса. Внешние потребители должны перестать требовать это поле: у встроенного outbound нет отдельного управляемого клиентского процесса.

```yaml
connections:
  - id: tt
    name: TrustTunnel
    type: link
    link: "tt://?REPLACE_WITH_EXPORTED_LINK"
```

Заполнитель не является рабочими реквизитами. Проверка сертификата TLS включена, если импортируемый профиль явно не отключает её. Если параметр экспорта невозможно представить во встроенной реализации, импорт возвращает ошибку, а не ослабляет настройки молча.

Встроенный импорт TrustTunnel отклоняет поля аутентификации client-random, URL подписок, разные порты в списке адресов и неподдерживаемые транспорты. Для IP с одинаковым портом выбирается один адрес (предпочтительно IPv4), без параллельных попыток внешнего клиента. Anti-DPI для HTTP/2 преобразуется во фрагментацию TLS; тайминги пакетов не идентичны внешнему клиенту. HTTP/3 с anti-DPI отклоняется. DNS-настройки ссылки не заменяют DNS KeenProxy.

Если ссылка содержит несколько IP-адресов с одинаковым портом, импорт выбирает первый IPv4 в порядке экспорта, иначе первый IP-адрес. Остальные адреса не сохраняются как автоматические резервные: при отказе выбранного узла встроенный клиент не перебирает другие адреса из ссылки.

При включённой проверке сертификата `custom_sni` должен совпадать с экспортированным `hostname` (регистр и завершающая точка не учитываются). Схема встроенного TLS не позволяет передавать одно SNI и проверять другое имя; такие профили отклоняются, а не проверяются относительно другой identity. Проверка сертификата автоматически не отключается.
