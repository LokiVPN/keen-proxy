# Руководство пользователя

!!! note "Предварительная версия серверного интерфейса"
    При первом запуске панель открывает [первую настройку](#first-run). После неё по адресу `/` открывается обзор. На вкладке **Подключения** видны сохранённые подписки и свои подключения. Для остальных настроек используйте [YAML-файл](getting-started.md) или [управляющий API](development.md#control-api) на loopback. В других разделах этого руководства ещё описаны элементы прежней панели.

Скриншоты ниже синтетические.

## Как открыть панель { #access-the-panel }

После успешной установки или обновления из командной строки установщик выводит URL панели. Вход в браузере выполняется через сеансы KeeneticOS (см. [вход через KeeneticOS](development.md#keenetic-auth)); сам HTTP API принимает только локальные процессы на роутере. Повторно узнать URL можно командой `keenproxy --url`: она читает существующий конфиг, не запускает службу и не меняет настройки. Для нестандартного конфига:

```sh
keenproxy --url --config /path/to/config.yaml
```

URL учитывает `api.listen`; при прослушивании всех адресов (`0.0.0.0` или `::`) используется первый частный IPv4-адрес настроенного LAN-интерфейса — тот же, который принимает вход через KeeneticOS. Если такого адреса нет, команда не подставляет выдуманный. При привязке к loopback панель доступна только с роутера или через подходящий SSH-туннель. См. [установку и обновление](getting-started.md#install-or-update-from-github).

### Вход по действующему сеансу KeeneticOS

Если [вход через KeeneticOS включён](development.md#keenetic-auth), войдите
в роутер по локальному IP-адресу с правами управления. В **«Приложениях»**
нажмите **«Открыть панель»** на карточке KeenProxy. После завершения сеанса
панель покажет экран входа со ссылкой на KeeneticOS.

## Первая настройка { #first-run }

Откройте KeenProxy под учётной записью роутера с правами управления. Вставьте HTTPS-ссылку на подписку из личного кабинета LokiVPN и нажмите **Проверить**. KeenProxy передаст провайдеру постоянный идентификатор устройства. Проверка может занять одно место в лимите подписки. На экране появятся поддерживаемые серверы, сообщение провайдера и доступные сведения о трафике, сроке действия и правилах маршрутизации. Сведения о маршрутизации взяты из профиля провайдера. KeenProxy проверит эти правила при включении подписки.

Если на роутере ещё нет сохранённой политики сети, нажмите **Включить**, чтобы сохранить подписку и включить выборочную маршрутизацию для домашней сети настроенного LAN-интерфейса. Сеть будет следовать профилю провайдера. Если профиля нет, трафик без совпадения с правилами пойдёт через подписку. Для первой настройки интерфейсу нужен частный IPv4-адрес.

Если политики сети уже настроены, нажмите **Настроить подписку** на **Обзоре**. Проверьте ссылку и нажмите **Добавить подписку**. Серверы появятся в списке основных подключений, а текущие политики маршрутизации сохранятся.

На **Обзоре** нажмите **Заменить ссылку**, чтобы снова открыть настройку. Проверьте новую ссылку и подтвердите замену кнопкой **Заменить ссылку**. Идентификатор подписки и резерв сохранятся вместе с маршрутизацией, настройками устройств и состоянием паузы. Учётные записи с правом просмотра могут открыть страницу с отключёнными элементами управления.

## 1. Посмотрите обзор

**Обзор** показывает состояние основного подключения, расход трафика и срок действия подписки, если провайдер передаёт эти данные, а также время последнего и следующего запланированного обновления. Если до окончания подписки осталось не более семи дней, появляется предупреждение. Кнопка **Обновить сейчас** ставит обновление подписки в очередь. При ошибке обновления на обзоре видны ошибка и последний известный срок действия. Счётчик устройств показывает, сколько обнаруженных устройств локальной сети охватывают действующие политики KeenProxy. Сводки маршрутизации и устройств ведут на соответствующие вкладки.

Когда узлы подписки недоступны, строка состояния показывает используемое резервное подключение или прямой резерв. Статус **Нет связи** появляется, если используемый маршрут не прошёл проверку или может только блокировать трафик. Это относится к встроенному резерву `block`, именованным блокирующим подключениям и селекторам, которые ведут только к таким подключениям.

График **Трафик через VPN** показывает за последние 30 минут трафик подключений, которые могут направлять его через туннель. Если в raw-группе sing-box есть и прямые, и туннельные подключения, на обзоре указано имя подключения, а график также учитывает прямой трафик этой группы.

Переключатель **Включён** приостанавливает или возобновляет маршрутизацию через VPN для всех устройств. На паузе все устройства работают напрямую. В поле **Основное подключение** выберите автоматическое переключение при сбое, режим балансировки, отдельный узел подписки или своё подключение. Выбор меняет подключение домашней сети и обновляет режим **Весь трафик через VPN**, если он использовал прежнее основное подключение.

Изменение применяется сразу при переключении или выборе подключения. Если JavaScript отключён, нажмите **Сохранить** рядом с элементом управления. Учётные записи с правом просмотра могут открыть обзор с отключёнными настройками.

## 2. Настройте соединение

Откройте **Подключения**. Таблица **Свои подключения** показывает протокол профиля, последний результат проверки и настроенную [цепочку резервов](routing.md#fallback-chains). Столбец **Вкл** включает и отключает профиль. Нажмите **Сохранить**, чтобы применить переключатели и резервы подписок, или **Отменить**, чтобы вернуться к сохранённым настройкам. Учётные записи с правом просмотра видят обе таблицы с отключёнными элементами управления.

Нажмите **Добавить подключение**. Режим **Вставить** распознаёт ссылку подключения, автономный экспорт Amnezia `vpn://`, конфигурацию WireGuard или AmneziaWG `.conf` либо sing-box JSON с одним профилем подключения. Режим **Из файла** принимает те же форматы размером до 2 МиБ. В режиме **Вручную** доступны WireGuard, VLESS, Shadowsocks, Trojan, Hysteria2 и SOCKS.

Нажмите **Проверить**, чтобы роутер проверил профиль и показал тип, сервер и SNI. Если поле сводки содержит значение пароля, ключа или другого реквизита подключения, мастер показывает **Скрыто**. Для нового подключения мастер предлагает название по протоколу с номером, например `VLESS 2`, и свободный идентификатор, например `vless-2`. Их можно изменить перед нажатием **Сохранить**. Подключение будет применено, и мастер вернёт вас к списку. Идентификатор начинается со строчной латинской буквы или цифры и содержит до 32 строчных латинских букв, цифр, дефисов или подчёркиваний. Выберите свободный идентификатор для своего подключения. Если срок проверки истёк или в другом окне изменили настройки, проверьте данные ещё раз. Замена профиля использует его идентификатор и ссылки из правил маршрутизации и резервирования.

Если идентификатор совпал с тегом маршрутизации, выберите другой. При ошибке ручного ввода исправьте отмеченное поле и заново введите реквизиты перед проверкой.

Импортируйте автономный outbound или endpoint sing-box. Проверка отклоняет явные ссылки на теги, например `detour` и `domain_resolver`, включая ссылки на теги, объявленные в том же JSON. KeenProxy настраивает маршрутизацию, DNS-разрешение и привязку к интерфейсам.

Нажмите на название ручного подключения, чтобы открыть его страницу. Задайте состояние переключателя и выберите **Резерв**, затем нажмите **Сохранить**. Страница показывает цепочку резерва. Список вариантов остаётся прежним при изменении переключателя. Кнопки **Проверить** и **Сохранить** проверяют оба параметра вместе. Если сочетание создаёт цикл маршрутизации, ошибка появляется под полем **Резерв**, а оба изменения остаются в форме. Кнопка **Проверить** также проверяет доступность сохранённого подключения по URL из настроек резерва, если подключение включено в сохранённой конфигурации.

Разделы **Скорость** и **Трафик по сайтам** показывают данные, которые KeenProxy собрал для этого подключения. График показывает данные за последние 30 минут. На странице селектора sing-box перечислены его участники со ссылками на страницы сохранённых подключений. Трафик встроенных участников **Напрямую** и **Блокировка** учитывается отдельно от страниц подключений.

Страница скрывает секретные параметры и сведения, которые повторяют другие значения профиля, в том числе закодированные. Администратор может нажать **Показать параметры** на текущей странице или **Заменить параметры**, чтобы снова открыть мастер для этого подключения. Замена профиля сохраняет историю трафика. Если подключение используется в других настройках, кнопка **Удалить** перечислит ссылки, которые нужно убрать перед удалением. После удаления новое подключение с тем же идентификатором начнёт собирать историю трафика с нуля.

При отключении остаются профиль, реквизиты и ссылки из правил. Туннель и проверки доступности останавливаются. Профили также можно задать в [конфигурации YAML](getting-started.md).

Группы, устройства, сети и настройки DNS сохраняют ссылки на отключённое соединение. Трафик идёт по его цепочке включённых резервов; если подходящего резерва нет, он блокируется, а не отправляется напрямую или к следующему правилу. Явно настроенный резерв **Напрямую** сохраняет свой смысл. DNS использует отдельную политику strict/direct: отключение соединения не должно открывать прямой путь DNS в строгом режиме.

В конфигурации YAML raw-профили sing-box сохраняют ссылки `detour` и селекторов на настроенный ID соединения. Если соединение отключено, его runtime-посредник использует ту же цепочку включённых резервов или блокирует трафик при их отсутствии; сохранённый raw-профиль не переписывается.

### Подписки { #native-subscriptions }

Чтобы настроить или заменить подписку, следуйте разделу [«Первая настройка»](#first-run). KeenProxy принимает списки Xray по HTTPS в виде обычного текста или Base64 объёмом до 2 МиБ и до 256 разных узлов. Если провайдер ограничивает выбор клиента, используйте его ссылку на список Xray или разрешите KeenProxy в настройках провайдера.

Блок подписки на вкладке **Подключения** показывает состояние списка, последний результат проверки HTTPS каждого узла и сообщения о правилах маршрутизации выбранного провайдера. Нажмите **Проверить** у нужного узла или **Проверить все узлы**. KeenProxy ставит проверки в очередь, а результаты обновляются по мере готовности. Изменения резерва и переключателей остаются в форме до нажатия **Сохранить** или **Отменить**. Время успешной проверки включает установку соединения. KeenProxy отправляет запрос на настроенный HTTPS-адрес проверки или адрес по умолчанию и проверяет сертификат сервера.

В поле **Резерв, если не отвечает ни один узел** выберите своё подключение, **Напрямую — без VPN** или **Нет — блокировать трафик VPN**, затем нажмите **Сохранить**. Если туннель своего подключения отключён, используются его настроенные резервы. Вариант **Резерв не настроен** сохраняет уже существующую настройку без резерва.

Выберите цель подписки в поле **Основное подключение** на **Обзоре**.

- При ручном выборе правило привязано к одному узлу. Если узел исчезнет из подписки, маршрут будет заблокирован, а при наличии у подписки [резерва](routing.md#subscription-reserve) трафик пойдёт в него.
- **Авто — при сбое на другой узел** начинает с порядка провайдера и переключается после устойчивого отказа активного узла. По умолчанию проверки идут каждые 15 секунд, а окно отказа составляет 60 секунд. Рабочий заменяющий узел остаётся выбранным после восстановления приоритетного узла. Метка **Текущий** указывает на выбранный узел, а **Недоступен** сообщает о неудачной проверке. В строке могут отображаться обе метки.
- **Балансировка: по очереди** распределяет последовательные новые подключения по подходящим узлам.
- **Балансировка: по сайту** закрепляет сайт за одним подходящим узлом для всех устройств. Если известно имя хоста, используется регистрируемый домен, иначе IP-адрес назначения.
- **Балансировка: по сессии** закрепляет подходящий узел за парой «IP-адрес устройства и сайт». Для одной подписки сохраняется до 1 024 пар. Привязка истекает после 30 минут бездействия или когда узел перестаёт подходить для балансировки.

Все три режима балансировки используют узлы, которые прошли последнюю проверку и поддерживают транспорт подключения. Если подходящих узлов для этого транспорта нет, новые подключения используют [резерв](routing.md#subscription-reserve) подписки, если он задан, или блокируются.

Нажмите **Обновить сейчас** на **Обзоре**, чтобы загрузить актуальный список и сведения от провайдера. При ошибке KeenProxy показывает статус обновления и сохраняет последний проверенный список. Храните ссылки на подписки в секрете. Они входят в полную резервную копию YAML.

### Профили AmneziaWG (экспериментальная сборка lx)

Импортируйте однопировый `.conf` AmneziaWG или вставьте его содержимое в мастер подключений. При наличии AWG-полей автоматически выбирается **AmneziaWG**. При сохранении подключения KeenProxy сохраняет исходный профиль. Храните файл приватно, поскольку внутри есть закрытый ключ туннеля и может быть предварительно согласованный ключ.

Эта сборка использует [sing-box-lx 1.14.4-lx.35](https://github.com/Leadaxe/sing-box-lx/releases/tag/v1.14.4-lx.35). Поддерживаются клиентские параметры AWG 2/3 и TCP/UDP приложений через userspace-endpoint WireGuard; внешний туннель использует UDP. Модуль AWG в ядре и отдельный демон не нужны. Неподдерживаемые поля, исполняемые команды и несколько пиров отклоняются, а не теряются при импорте.

Для автономного клиентского экспорта Amnezia `vpn://` вставьте ссылку целиком или загрузите текстовый файл либо `.vpn` со ссылкой. KeenProxy декодирует экспорт локально. Если внутри несколько AWG-профилей, выберите один и снова нажмите **Проверить**. Проверьте название и идентификатор, затем сохраните выбранную клиентскую конфигурацию AWG.

Поддерживаются сжатые и несжатые автономные экспорты с допустимой версией формата (отсутствует, 0 или 1). Размер закодированной ссылки ограничен 2 МиБ, декодированного JSON — 1 МиБ. В одном экспорте допускается не более 32 кандидатов AWG и не более 1 МиБ нативных профилей суммарно; при превышении лимита экспорт отклоняется целиком, без частичного импорта. Повреждённые экспорты, неподдерживаемые параметры протокола, ключи сервиса/подписки и административные экспорты без клиентских ключей отклоняются. Ссылка `vpn://` не обязательно содержит готовый туннель: нужен **экспорт клиентского подключения**, а не ключ активации подписки.

Для ограничения расхода памяти роутера junk-серия ограничена 256 пакетами и 1 МиБ полезной нагрузки на одно рукопожатие в худшем случае. Ограничение действует для нативных профилей AWG и raw-endpoint WireGuard после декодирования параметров ядром.

Поле `DNS` профиля не заменяет настройки DNS KeenProxy. Соединение по-прежнему выбирают существующие правила и failover; `AllowedIPs` не устанавливает системные маршруты. Для UDP приложений нужен перехват **TPROXY**. Существующее **отклонение UDP/443 участвующих клиентов сохраняется**: импорт AWG не включает клиентский QUIC. Активация подписок Amnezia, настройка серверов и интеграция с API сервиса не поддерживаются.

В YAML сохраните профиль многострочной строкой:

```yaml
connections:
  - id: awg
    name: AmneziaWG
    type: amneziawg
    amneziawg: |
      [Interface]
      PrivateKey = <client-private-key-base64>
      Address = 10.77.0.2/32
      Jc = 3
      Jmin = 40
      Jmax = 80
      S1 = 20
      S2 = 30
      H1 = 1001
      H2 = 1002
      H3 = 1003
      H4 = 1004
      [Peer]
      PublicKey = <server-public-key-base64>
      Endpoint = vpn.example.com:51820
      AllowedIPs = 0.0.0.0/0
```

Замените заполнители и параметры обфускации значениями из экспорта своего сервера. Перед откатом на сборку с официальным sing-box удалите или замените подключения AmneziaWG и сохраните конфигурацию, чтобы её мог загрузить старый движок.

### Совместимость sing-box-lx { #sing-box-lx-compatibility }

Обе сборки поддерживают XHTTP и встроенный TrustTunnel наряду с существующими VLESS, REALITY и AWG. Вставьте экспортированную сервером ссылку или один готовый sing-box outbound в мастер подключений. Нажмите **Проверить**, просмотрите профиль и нажмите **Сохранить**, чтобы применить его.

Ссылки VLESS сохраняют параметр `encryption`, а не отбрасывают его. Гибридный обмен ключами REALITY и шифрование VLESS — разные механизмы; ни один не добавляет поддержку подписей Xray `pqv` или `spiderX`. Используйте параметры своего сервера, а не включайте шифрование произвольно.

Поддерживаемые параметры ссылок:

| Возможность | Параметры |
| --- | --- |
| XHTTP | `type=xhttp` или `splithttp`, `host`, `path`, `mode=auto/packet-up/stream-up/stream-one`, URL-кодированный JSON `extra` и `xmux` |
| Шифрование VLESS | `encryption=mlkem768x25519plus.…`; `none` отключает этот слой |
| REALITY | `key_share=hybrid` или `classical` (алиас `keyShare`), вместе с `pbk`, `sid`, `sni` и `fp` |
| Фрагментация TLS | Явные булевы значения `fragment`, `record_fragment` (алиас `recordFragment`) и длительность `fragment_fallback_delay` (алиас `fragmentFallbackDelay`) |

Некорректные флаги, неподдерживаемые опции XHTTP, непустые `pqv`/`fm` и нестандартные значения `spx` отклоняются при импорте. Для опций движка без преобразования из ссылки остаётся готовый sing-box JSON; при применении его проверяет движок.

Для XHTTP (`type=xhttp` или `splithttp`) с `flow=xtls-rprx-vision` нужен включённый слой VLESS `encryption`. Ссылки с таким сочетанием без encryption или с `encryption=none` отклоняются при импорте; одного TLS/REALITY недостаточно. Профили XHTTP/Vision с включённым шифрованием остаются поддерживаемыми.

Полная сборка включает QUIC/HTTP/3. Lite сохраняет TCP/TLS-транспорты, в том числе XHTTP через HTTP/1.1 или HTTP/2 и TrustTunnel через HTTP/2; профили только с HTTP/3 требуют полной сборки. Этот выбор транспорта движка не меняет политику перехвата клиентского UDP/443.

TrustTunnel использует `type: link` и полную экспортированную ссылку `tt://?…`. Старые секции `type: trusttunnel` преобразуются при загрузке и сохраняются как ссылки при применении; `binary` и `socks_port` больше не управляют отдельным процессом. Ранее установленные внешние клиенты не удаляются, но больше не используются. Перед миграцией сохраните старый конфиг, если нужен откат на сборку с внешним клиентом.

Обновление и `--uninstall` оставляют старые файлы `bin/trusttunnel_client` и `share/keenproxy/trusttunnel/` внутри каталога установки (обычно `/opt`). Убедившись, что встроенное соединение работает, удалите их вручную, только если они не используются другими сервисами и больше не нужны для отката на внешний клиент. Сначала сохраните старую конфигурацию; сгенерированные файлы клиента могут содержать реквизиты доступа.

API состояния больше не возвращает поле `trusttunnel` со статусом внешнего процесса. Внешние потребители должны перестать требовать это поле: у встроенного outbound нет отдельного управляемого клиентского процесса.

```yaml
connections:
  - id: tt
    name: TrustTunnel
    type: link
    link: "tt://?REPLACE_WITH_EXPORTED_LINK"
```

Заполнитель не является рабочими реквизитами. Проверка сертификата TLS включена, если импортируемый профиль явно не отключает её. Если параметр экспорта невозможно представить во встроенной реализации, импорт возвращает ошибку, а не ослабляет настройки молча.

Встроенный импорт TrustTunnel отклоняет поля аутентификации client-random, URL подписок, разные порты в списке адресов и неподдерживаемые транспорты. Для IP с одинаковым портом выбирается один адрес (предпочтительно IPv4), без параллельных попыток внешнего клиента. Anti-DPI для HTTP/2 преобразуется во фрагментацию TLS; тайминги пакетов не идентичны внешнему клиенту. HTTP/3 с anti-DPI отклоняется. DNS-настройки ссылки не заменяют DNS KeenProxy.

Если ссылка содержит несколько IP-адресов с одинаковым портом, импорт выбирает первый IPv4 в порядке экспорта, иначе первый IP-адрес. Остальные адреса не сохраняются как автоматические резервные: при отказе выбранного узла встроенный клиент не перебирает другие адреса из ссылки.

При включённой проверке сертификата `custom_sni` должен совпадать с экспортированным `hostname` (регистр и завершающая точка не учитываются). Схема встроенного TLS не позволяет передавать одно SNI и проверять другое имя; такие профили отклоняются, а не проверяются относительно другой identity. Проверка сертификата автоматически не отключается.



## 3. Добавьте группу маршрутизации

Откройте **Правила → Белый список**. Создайте группу, задайте имя, выберите целевое соединение либо **Напрямую**/**Блокировать**, добавьте домены или адреса. Например, направьте `work.example.com` через профиль Netherlands. Проверьте импортируемые записи перед подтверждением; выбор стран задаёт более широкую политику.

Чтобы сменить маршрут нескольких доменных групп или групп стран, отметьте их флажками, выберите цель в панели **Изменить маршрут** и проверьте список. Скрытые фильтром группы могут оставаться выбранными. Нажмите **Сохранить в черновик**, затем **Применить**.

Раскройте запись, чтобы посмотреть DNS-наблюдения и срок действия адресов. Наличие IP само по себе не доказывает, что трафик приложения прошёл через нужный туннель.

Переключатели позволяют приостановить целую группу или отдельное правило домена/IP, не удаляя значение. У групп стран/категорий есть переключатели группы и отдельных условий. Отключённые элементы остаются видимыми, а счётчики активных и всех правил показывают разницу между сохранёнными и действующими правилами. Выключение группы сохраняет индивидуальные состояния внутри: при включении отдельно приостановленные правила не включаются автоматически.

Выключенная группа или правило пропускается, а не блокируется: маршрут определяют оставшиеся правила и политика устройства. В частности, отключённое правило блокировки перестаёт блокировать. Выключенные доменные правила не участвуют в действующих наборах DNS-правил и не инициируют фоновое разрешение адресов. Группа стран/категорий без активных условий не действует даже в режиме **Все, кроме** и не превращается в правило на весь интернет. Проверьте общий черновик и нажмите **Применить** для изменения действующего поведения.

В YAML переключатели соединения и группы используют `disabled: true`. Состояния отдельных правил сохраняются в `disabled_entries`, `disabled_countries` и `disabled_categories`; исходные записи и условия остаются на месте. При отсутствии этих полей прежнее поведение сохраняется. Старые версии отклоняют неизвестные поля состояний: перед откатом подготовьте и проверьте совместимую конфигурацию. Удаление полей включает соответствующие элементы обратно, поэтому сначала проверьте получающиеся маршруты.

![Группы доменов, маршруты и сведения об адресах](../assets/screenshots/ru-rules.png)

Настройка с иллюстрациями, исключениями стран и приоритетом правил описана в разделе [Правила по странам](routing.md#country-rules).

## 4. Выберите устройства и сети

Откройте **Устройства**. В списке видны обнаруженные устройства локальной сети и сохранённые устройства, которые сейчас не в сети. Если имя задано вручную, оно имеет приоритет. Устройство без имени можно узнать по MAC-адресу.

Включите **VPN** для устройства, чтобы применять к нему выбранные правила маршрутизации. Выключите переключатель, чтобы трафик шёл без перехвата KeenProxy. Кнопка **Включить всем** пропускает устройства, которым для изменения режима нужна цель VPN, и показывает их количество. Кнопка **Выключить всем** выключает VPN для всех устройств в списке. Устройство, использующее полный туннель, в том числе по политике сети, сохраняет режим до изменения своего переключателя или общего действия, которое меняет его состояние.

Переключатель **Новые устройства сразу используют VPN** задаёт политику по умолчанию для домашней сети. Когда вы нажимаете **Сохранить**, KeenProxy запоминает показанные состояния переключателей, включая выключенный VPN у пропущенных устройств. При смене политики устройства из списка сохраняют свои состояния. При сохранении KeenProxy также проверяет текущие адреса устройств с раздельной маршрутизацией. Если адрес больше не входит в сеть, для которой доступна цель VPN, проверьте отмеченные устройства перед повторным сохранением.

## 5. Проверьте и примените

Панель изменений появляется, когда черновик отличается от сохранённой конфигурации. Просмотрите правки на всех экранах и один раз нажмите **Применить**. Дождитесь успеха. При ошибке проверки/применения прочитайте сообщение и исправьте черновик. **Отменить** восстанавливает последний сохранённый снимок.

## 6. Проверьте результат

В разделе **Диагностика → Состояние** видны состояние ядра и слушателя DNS, режим перехвата, время применения конфигурации, база стран, число восстановлений правил фаервола с запуска, а также нагрузка на процессор и память роутера и KeenProxy.

Нажмите **Запустить проверку**, чтобы проверить HTTP, HTTPS с проверкой сертификата и передачу 64 КиБ через применённое основное подключение. Для группы показывается текущий маршрут в виде **группа → выход**. Если группа с несколькими выходами выбрала прямой путь или блокировку либо выбранный маршрут использует настроенный резерв, проверка основного маршрута VPN пропускается. Для замера выход VPN должен быть доступен без промежуточного маршрута. В результатах видны проверенный узел подписки и время замера. Строка DNS показывает состояние слушателя. Фактический путь DNS и трафика проверяйте [с нужного устройства](network-flow.md#how-to-trace-one-request).

### Выгрузите журналы и диагностику { #export-journals }

Под учётной записью с правом управления откройте **Диагностика → Отчёт для поддержки → Скачать ZIP**. См. [состав выгрузки и что проверить перед отправкой](troubleshooting.md#download-the-diagnostic-zip).

### Проверьте, какое правило сработало

В **Журнале** переключайтесь между вкладками **Маршрутизация**, **Аудит** и **Система**. В **Маршрутизации** флажок **Группировать повторы** объединяет совпадающие загруженные записи в окнах по 30 секунд. Раскройте группу, чтобы увидеть записи, или снимите флажок для просмотра по одной. Поиск и фильтры сужают выборку. Запись показывает выбранный выход. Успешное подключение и передачу проверяйте отдельно в самом приложении. Новые записи в браузерном демо создаёт локальная симуляция.

События восстановления сторожа содержат неудачную проверку firewall и результат проверки после восстановления. ZIP сохраняет безопасные структурированные сведения. Подробнее в [диагностике сторожа](troubleshooting.md#why-does-the-watchdog-restore-interception-rules).

## 7. Найдите нужный раздел настроек и сделайте резервную копию

Откройте **Настройки** через значок шестерёнки. На узком экране раздел выбирается из выпадающего списка. По умолчанию открывается **DNS**. Для резервных копий есть вкладка **Конфигурация YAML**. Вкладка **Сеть и перехват** содержит режим REDIRECT/TPROXY и интерфейсы. Во вкладке **Доступ к панели** находятся адрес прослушивания. **Базы стран** показывают состояние GeoIP, а **Язык и тема** управляют настройками браузера. Сетевые настройки и доступ к панели сохраняются через общую кнопку **Применить**. После смены адреса прослушивания панели нужно перезапустить службу. У **Обновлений** отдельные кнопки.

Откройте **Настройки → DNS** и выберите основной сервер. Резервный сервер необязателен: чтобы удалить его, очистите выбор. Выберите провайдера и протокол из списка или откройте **Свой DNS-сервер** и введите IP-адрес либо URL для DoH, DoT или UDP. В списке есть Cloudflare, Google Public DNS, Quad9, AdGuard, Яндекс DNS, Cisco OpenDNS, CleanBrowsing и Control D. У каждого варианта указана политика фильтрации. KeenProxy сначала обращается к основному серверу и переключается на резервный, если он настроен, когда основной недоступен. Серверы должны отличаться. Дополнительные серверы, Bootstrap IP и адрес прослушивания находятся в **Дополнительных параметрах**. Маршрут DNS и поведение при отказе туннеля настраиваются отдельно. В импортируемом YAML также можно указать один сервер в списке `dns.upstreams`.

Если очистить поле **Резервный DNS**, когда настроены дополнительные серверы, первый из них займёт освободившееся место. Порядок остальных серверов не изменится. Чтобы оставить только основной, сначала удалите все дополнительные серверы, затем очистите поле резервного и нажмите **Применить**.

Если запросы локального DNS-резолвера перенаправляются обратно к нему, откройте **Дополнительные параметры → Исключения из перехвата DNS по IP источника**, добавьте IPv4-адрес самого резолвера (не вышестоящего сервера) и нажмите **Применить**. Чтобы вернуть перехват, удалите адрес и снова примените настройки. Ключ YAML и границы исключения описаны в разделе [DNS](routing.md#dns).

Конфигурация хранится в YAML-файле на роутере. Её можно сохранить или отредактировать вручную по SSH; копии держите приватными, так как они содержат учётные данные соединений. KeenProxy читает файл при запуске.

### Мягкий лимит памяти { #soft-memory-limit }

Открывайте **Настройки → Системные**, только если роутеру не хватает памяти. **Мягкий лимит памяти Go, МиБ** — необязательная рекомендация для среды выполнения Go; она распространяется на KeenProxy и встроенный sing-box. Снижение лимита учащает сборку мусора, увеличивает нагрузку на ЦП и может снизить скорость соединения. Если проблем с памятью нет, оставьте поле пустым.

Это не жёсткий предел RSS процесса; настройка не охватывает всю память операционной системы. Go может превысить указанное значение. Оставляйте запас для прошивки роутера, сетевых буферов и других служб. Подробнее — в [руководстве Go по лимиту памяти](https://go.dev/doc/gc-guide#Memory_limit).

Общая кнопка **Применить** сохраняет и активирует значение. Изменение только этого поля не требует перезапуска службы или sing-box; сохранённый лимит также устанавливается при запуске. Пустое поле использует лимит Go, заданный до запуска демона, в том числе через `GOMEMLIMIT`; если лимит не задан, KeenProxy использует **768 МиБ (805306368 байт)**. Явное значение в панели имеет приоритет. Чтобы вернуть стандартный режим, очистите поле и примените изменения. Явный `GOMEMLIMIT=off` сохраняет режим без унаследованного ограничения.

Например, явно заданная рекомендация 400 MiB сохраняется так:

```yaml
system:
  memory_limit_mib: 400
```

Допустимы только положительные целые значения в MiB. Для удаления настройки уберите ключ `memory_limit_mib`, а не задавайте ноль.

## 8. Установите или откатите релиз

В разделе **Диагностика → Отчёт для поддержки** видны запущенный релиз, вариант сборки, архитектура и короткий хеш коммита. Нажмите **Скопировать**, чтобы скопировать сведения о сборке. У локальной сборки может не быть тега релиза или хеша. В диагностическом ZIP эти данные находятся в `status.json`.

Откройте **Диагностика → Обновления**, чтобы проверить наличие релиза, установить доступное обновление или вернуться к записанной предыдущей версии. Подтвердите версию на следующем экране и дождитесь, пока служба снова ответит. Для установки по расписанию включите **Устанавливать автоматически**, выберите местное время роутера и сохраните. Первоначальная настройка и условия отката описаны в разделе [Обновление из панели](getting-started.md#update-from-the-panel).
